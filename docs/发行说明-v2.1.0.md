# TermDeck v2.1.0

TermDeck 是一个 SSH / SFTP 终端客户端：可拖拽、可停靠的终端窗格，加上会话树、主机批量管理、
端口转发、对象存储与 REST 工具页。

**v2.1.0 加上了 macOS** —— 同一份代码现在在两个平台上都能装、能开、能起本地 shell，
快捷键按各平台的习惯给默认值。Windows 上的功能没有变化。

## 下载

### Windows（x64）

| 文件 | 说明 |
| --- | --- |
| **`TermDeck-Setup-2.1.0.exe`** | 安装版（NSIS）：装到本机、带开始菜单与桌面快捷方式 |
| **`TermDeck-2.1.0-win-x64-portable.zip`** | 解压即用：解开双击 `TermDeck.exe` 就能跑，建议用这个 |
| `TermDeck-2.1.0-x64.exe` | 单文件便携版：一个 exe，首次运行自解压 |

### macOS

| 文件 | 说明 |
| --- | --- |
| **`TermDeck-2.1.0-arm64.dmg`** | Apple Silicon（M 系列）安装盘 |
| **`TermDeck-2.1.0-x64.dmg`** | Intel Mac 安装盘 |
| `TermDeck-2.1.0-arm64.zip` / `TermDeck-2.1.0-x64.zip` | 同一个 app 的压缩包，解压后拖进「应用程序」 |

macOS 的构建在 GitHub Actions 上完成（dmg 需要 Mac 上的 `hdiutil`），
产物里各带一份校验值：`SHA256SUMS-2.1.0-mac-arm64.txt` 与 `…-mac-x64.txt`。
Windows 三个产物的校验值在 `SHA256SUMS-2.1.0.txt` 里。

**macOS 版没有代码签名、也没有公证**（这个项目没有 Apple 开发者账号），所以第一次打开
会被 Gatekeeper 拦住：

1. 在「访达」里 **右键（或按住 Control 点击）TermDeck.app → 打开**，再在弹窗里点一次「打开」。
   直接双击只会看到"无法验证开发者"。
2. 或者解除隔离标记，之后就能正常双击：

   ```bash
   xattr -dr com.apple.quarantine /Applications/TermDeck.app
   ```

3. **换位置之后可能要重新输一次密码**：加密用的 `safeStorage` 在 macOS 上走钥匙串，
   应用被移动（或换了签名）时，之前存下的密文可能取不回来。

**Windows 那边照旧**：安装包没有签名证书，SmartScreen 会拦一下，点「更多信息 → 仍要运行」即可。

## macOS 上这次做了什么

- **本地 shell 起得来**：按 `$SHELL` → `/bin/zsh` → `/bin/bash` → `/bin/sh` 的顺序挑一个真正
  存在的 shell，**不带** Windows 那套参数。同时补上 `PATH`（`/opt/homebrew/bin`、`/usr/local/bin`）
  与 `TERM`/`LANG` —— 从访达启动的应用拿不到登录 shell 的环境，不补的话 `brew` 装的东西在里面
  "不存在"，非 ASCII 输出也会乱码。
- **应用菜单**（这条最要命）：macOS 上建了最小的 App / Edit / Window 菜单。**`Cmd+C` / `Cmd+V` /
  `Cmd+A` 这些是 Edit 菜单的 role 提供的** —— 没有菜单，不只是"我们没绑定"，是系统根本不给。
  Windows / Linux 上仍然没有应用菜单（那一边本来就不需要，而且菜单会跟 `Alt` 快捷键打架）。
- **快捷键按平台给默认值**：mac 上用 `Cmd` 作默认修饰键（`Cmd+T` 新建连接、`Cmd+,` 打开设置……），
  **`Cmd+W` 是"关闭当前窗格"**，系统的关窗挪到 `Cmd+Shift+W`；`Ctrl` 相关的键位在终端里仍然归 shell
  （`Ctrl+W` 还是 readline 的"删掉前一个词"，这一点在 mac 上同样成立）。
  老配置里**恰好等于旧默认值**的会被迁移成新默认，你自己改过的一律原样保留。
- **字体**：默认等宽字体在 mac 上是 `SF Mono` → `Menlo` → `Monaco`；字体选择器会用
  `system_profiler` 读这台机器上真实装了什么。
- **打包**：出 `dmg` 与 `zip`，**arm64 与 x64 分开两个包**（不做 universal）。mac 的构建由
  GitHub Actions 的 macOS runner 完成 —— dmg 需要 `hdiutil`，只有在 Mac 上才打得出来。
- **退出仍然先问一句**：`Cmd+Q`、菜单里的「退出」、关窗，都会先弹确认，不会静默把一堆
  SSH 会话一次性关掉。

## Windows 上变了什么

**没有功能变化。** 默认字体、默认键位、应用菜单、退出确认这几处都加了断言，逐条比过与 2.0.0 一致。

## 校验

```powershell
Get-FileHash -Algorithm SHA256 .\TermDeck-Setup-2.1.0.exe
```

```bash
shasum -a 256 TermDeck-2.1.0-arm64.dmg
```

和附件里对应的 `SHA256SUMS-*.txt` 对一下即可（Windows 那份叫 `SHA256SUMS-2.1.0.txt`，
mac 两个架构各自一份）。

## 已知边界（写在明处）

- **macOS 产物未签名、未公证** —— 首次打开要右键「打开」，或按上面的 `xattr` 处理。
- 首批 macOS 构建由 CI 产出；**真机上的人工验收清单**在
  [docs/交接-macOS适配.md](交接-macOS适配.md) 第 9 节，逐条打勾。
  串口页在 Mac 上应当能列出 `/dev/cu.*`，但这条只能真机确认。
- 界面里还有几处文案把快捷键写死成 `Ctrl+…`（抽屉底部"新建连接"的悬浮提示、重连说明里的
  `Ctrl+R`），在 mac 上应当显示 `Cmd+…`；已在下一批的待办里。
- **S3 页与端口转发页目前仍是英文界面**（词汇表里还没有这两页的条目）；其余界面中英可切。
- `~/.ssh/config` 导入**还没做**（README 的状态表里标着 ⬜）。
- Windows 只提供 x64 构建。
