# TermDeck v2.6.1

TermDeck 是一个 SSH / SFTP 终端客户端：可拖拽、可停靠的终端窗格，加上会话树、主机批量管理、
端口转发、对象存储与 REST 工具页。Windows 与 macOS 都有构建。

**v2.6.1 是两处修复**，都在 macOS 这一侧：**字体列表读成了字体文件名**，以及
**mac 打包配置把架构锁死**（`--arm64` / `--x64` 因此失效，CI 的两个 runner 会各打出一个坏包）。
界面与功能没有其它变化。

## 修复

### macOS 26：设置里的字体下拉显示的是文件名

`system_profiler SPFontsDataType -json` 在 macOS 26 上把每条字体的**文件名**放在顶层 `_name`
（本机 294 个条目里 292 个带扩展名，如 `Times New Roman Bold.ttf`），真正的族名移到了
`typefaces[].family`。我们原来遍历文档里所有 `_name`，于是字体下拉里出现的是文件名字符串，
而不是能用的族名。

现在优先取 `typefaces[].family`，只有在文档里没有这个字段时才回退 `_name`，并且过滤掉文件名
与含 `/` 的名字。本机实测枚举出 **342 个族名**（`Times New Roman`、`圆体-繁`…），真机探针
102/102 全过。代价写在明处：**某个字体如果在报告里没有 `family` 字段，它就不会出现在列表里**。

### mac 打包：命令行指定的架构被配置顶掉

`build.mac.target` 里写死了 `arch: ["arm64","x64"]`，它会覆盖命令行开关：在 arm64 机器上跑
`npm run dist:mac -- --arm64`，仍然会把 x64 包一起打出来 —— 而那个包里的原生模块是 **arm64** 的
（`pty.node`、ssh2 的 `sshcrypto.node`、`cpu-features` 的 `cpufeatures.node`），到 Intel 机器上
本地 shell 与 SSH 都是坏的。

同样的原因，CI 里「一个 runner 只打一个架构」从来没有真正生效：两个 runner 都会各打两个架构，
各自上传的 artifact 里都带着另一个架构的坏包。现在配置里只留 `target: ["dmg","zip"]`，
架构交给命令行 / runner 决定；`smoke:mac` 里补了两条断言盯着这件事（配置不许锁死架构、
CI 必须把矩阵架构传进 `dist:mac`）。

> 如果你之前拿过 2.6.0 的 Intel mac 包：它是在 arm64 机器上打出来的，包里原生模块的架构不对，
> 请换用 2.6.1 由 Intel runner 产出的那一份。

## 已知边界（写在明处）

- **macOS 产物未签名、未公证**：第一次打开要右键「打开」，或
  `xattr -dr com.apple.quarantine /Applications/TermDeck.app`。
- **Mac 上整套闸门目前跑不绿**（不是这一版引入的，三类原因）：
  1. `npm run verify:fast` 在 macOS 上根本跑不起来 —— 脚本里写死了 `cmd.exe`，是 Windows 专用；
  2. `npm run verify` 会停在第一个套件 `smoke:deps`，它要 `~/.ssh/id_rsa` 与本机 sshd；
  3. 一批探针把 Windows 的默认值写死了（`Ctrl+W`、`Alt+数字`、选中即复制，以及硬编码的
     `D:\` 路径），在 mac 上按设计就不成立。
  在 mac 上真正能当依据的是 `npm run smoke:mac`（102 条）与打包版自检。
- **Windows 只提供 x64 构建。**
- S3 页与端口转发页仍是英文界面。
- 快捷键、菜单、主题、REST 工作台、`~/.ssh/config` 导入等与 v2.6.0 一致。

## 校验

```bash
shasum -a 256 TermDeck-2.6.1-arm64.dmg
```

```powershell
Get-FileHash -Algorithm SHA256 .\TermDeck-Setup-2.6.1.exe
```

和附件里对应的 `SHA256SUMS-*.txt` 对一下即可。

## 为什么 Windows 包不能在 mac 上打

不是「没试」，是打出来的东西不能用：

- `@lydell/node-pty` 是按平台 + 架构分的可选依赖，`npm ci` 在 mac 上只装 `node-pty-darwin-arm64`，
  **没有 win32 的 node-pty** → 打包版开不了本地 shell；
- ssh2 的 `sshcrypto.node` 与 `cpu-features` 的 `cpufeatures.node` 是安装时在本机编译的，在 mac 上是
  Mach-O arm64 → 到 Windows 上加载不了；
- `scripts/zipdist.cjs` 明确拒绝非 win32，而 `pack:zip` 产的三件之一（便携 zip）正是它出的。

所以在 mac 上打 Windows 包，只会得到和上面那个坏掉的 Intel mac 包同一类的东西。要么在那台
Windows 机器上跑 `npm run dist:win` + `npm run pack:zip`，要么补一条 windows CI（照
`.github/workflows/mac.yml` 的形状写）。
