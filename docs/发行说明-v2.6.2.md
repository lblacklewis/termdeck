# TermDeck v2.6.2

TermDeck 是一个 SSH / SFTP 终端客户端：可拖拽、可停靠的终端窗格，加上会话树、主机批量管理、
端口转发、对象存储与 REST 工具页。Windows 与 macOS 都有构建。

**v2.6.2 只修 macOS 的安装问题**：v2.6.1 的 mac 包签名是坏的，下载后双击会被 Gatekeeper 拦成
**「"TermDeck" 已损坏，无法打开。你应该将它移到废纸篓。」** —— 那不是文件传坏了，是包里没有有效签名。
这一版给 mac 产物做了 ad-hoc 签名，右键「打开」这条路恢复可用。

> 已经在别的机器上装了 v2.6.1 的 mac 包、看到「已损坏」的：不用重下也能救 ——
> 把 app 拖进「应用程序」后执行 `sudo xattr -dr com.apple.quarantine /Applications/TermDeck.app`
> 即可打开。但建议还是换 v2.6.2，签名有效的包以后升级不会再遇到这个提示。

## 修复

### mac 包「已损坏」：签名没做

`build.mac` 里没有签名配置，而 CI 又设了 `CSC_IDENTITY_AUTO_DISCOVERY=false`，于是
electron-builder **整个跳过签名**。它不签，但它在打包时改过 app 包（改名可执行文件、写 Resources），
于是车里留着的是链接器当初嵌进去的那份 ad-hoc 签名 —— 内容早就不匹配了：

```
$ codesign --verify --deep --strict TermDeck.app
TermDeck.app: code has no resources but signature indicates they must be present   # 签名无效
```

这种包在**没有隔离属性**的本机可以直接跑（我们自己测的时候就是），可一旦是从浏览器 / 微信下载来的
（带 `com.apple.quarantine`），macOS 就把它判成损坏：

```
$ xattr -w com.apple.quarantine "0083;...;Safari;" TermDeck.app
$ ./TermDeck.app/Contents/MacOS/TermDeck ...
Killed: 9        # 执行被拦，双击就是那个「已损坏，无法打开」的弹窗
```

修法是显式要求 ad-hoc 签名（`build.mac.identity: "-"`）。ad-hoc 签名下 hardened runtime 会拒掉
Electron 那些签名不同的 framework，所以同时把 `hardenedRuntime` 关掉。改完之后：

```
$ codesign -dv TermDeck.app     →  Identifier=com.lblacklewis.termdeck  flags=0x2(adhoc)
$ codesign --verify --deep --strict TermDeck.app
TermDeck.app: valid on disk
TermDeck.app: satisfies its Designated Requirement
```

`smoke:mac` 里补了一条断言盯着这两个配置项（少一个就会再发出「已损坏」的包）。

## 已知边界（写在明处）

- **ad-hoc 签名 ≠ 正式签名**：仍然没有 Apple 开发者账号，所以不公证；首次打开还是要右键「打开」，
  或在系统设置里放行。要想双击就开、没有提示，只能走正式签名 + 公证（$99/年）。
- **v2.6.1 的 mac 产物是坏的**，已经在那一页上标注，请改用 v2.6.2。
- S3 页与端口转发页仍是英文界面。
- 快捷键、菜单、主题、REST 工作台等与 v2.6.1 一致。

## 为什么 Windows 包不能在 mac 上打

不是「没试」，是打出来的东西不能用：`@lydell/node-pty` 是按平台 + 架构分的可选依赖，`npm ci` 在
mac 上只装 `node-pty-darwin-arm64`（没有 win32 的）；ssh2 的 `sshcrypto.node` 与 `cpu-features` 的
`cpufeatures.node` 是安装时本机编译的，在 mac 上是 Mach-O arm64；`scripts/zipdist.cjs` 也明确拒绝
非 win32。所以在 mac 上打 Windows 包只会得到架构不对的坏包。要么在那台 Windows 机器上
`npm run dist:win` + `npm run pack:zip`，要么补一条 windows CI。
