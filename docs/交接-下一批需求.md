## 每项的关键决定（别轻易改）

- **重连不劫持活着的窗格**。`deadPaneFor()` 只认 `endedSessionsRef` 里已经结束的会话；
  活着的窗格永远不接管 —— 那是"复制连接"的职责。改这里之前先看 `smoke/reconnect`。
- **telnet 是自己实现的字节状态机**（`TelnetBackend.ts`），不是库：只需要协商 NAWS/TTYPE/SGA，
  其余一律拒绝。串口用可选依赖 `serialport`，缺了要**明确报"不可用"**而不是崩。
- **登录后命令**由 `runPostConnect()` 发：首条等 900ms，之后每条 +400ms。太快会在 motd 里丢。
- **隧道永不自动重连**。启动时只恢复定义。开机悄悄挂起一条生产链路是这个功能最容易造成的意外。
  另外：改目标的隧道**必须停掉**（`sameTarget()`，改名不算改指），否则界面显示新参数、流量还
  走旧通道。
- **REST 请求走主进程**。渲染层是 `file://`，页面里 `fetch` 受 CORS 限制，而这个工具的目标恰恰
  是不发 CORS 头的本机/内网服务。同理：渲染层自己从不碰网络，S3 也走主进程。
- **REST 是"轻量"的**：一张屏，无集合/环境变量/测试运行器；模板是形状不是保存的请求；
  自签证书必须每次明确勾选。
- **S3 secret key 只留内存、不落盘**（`rememberSecret` 为真才存）。S3 工具不引 AWS SDK，
  SigV4 手写在 `src/main/s3/sigv4.ts`。
- **`sanitiseTree()` 是读路径白名单**：`SavedSession` 上新加的字段（`kind`/`serial`/
  `postConnectCommands`）必须同时加进去，否则存了也在重启后消失。这个坑踩过一次。

`get-vanilla` 与 S3 带 Range 示例**逐字符**比对签名，再由 mock 服务端从收到的字节重算一遍。
改签名相关代码后先跑它，别等 403。

## 踩过的坑（这批新增的）

1. **探针里不能有反引号和 `\d`、`\/` 这类反斜杠** —— 它们会被注入用的模板字符串吃掉。
   `npm run check:probes` 会拦（48 个文件逐个解析），改完探针立刻跑它。
2. **`.NET [IO.File]` 不认 PowerShell 的 `cd`**：一律写绝对路径。曾经因为相对路径写出过一个
   0 字节的 `package.json`，esbuild 直接报 "Unexpected end of file in JSON"。
3. **PowerShell 双引号里反引号是转义符**：做替换时锚点里有反引号（比如注释里的 `` `window.termdeck` ``）
   就必须用单引号 here-string，否则锚点永远不匹配。更稳的做法是 `edit` 工具。
4. **`features3` 在整链里曾报 46/50**：不是回归，是窗口丢了系统前台、xterm 不画光标。
   现在探针先要焦点、再等光标元素，并把这一前置条件单独断言成一条。
5. 探针断言**不要写恒真表达式**（`x || true`）—— 写出来的当天就该删。
