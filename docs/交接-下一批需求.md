## bug 9 的三处改动（一个 bug 三处才修得动）

1. **主进程在会话退出后保留蓝图**（`session:exit` 不再 `blueprints.delete`）。蓝图是这个窗格
   "怎么连上去的"唯一记录：主机、凭据、私钥、端口。没有它，一个 quick connect 断掉之后
   Reconnect 无从下手。释放点在 `session:close`（窗格关掉时），所以不会累积 —— 在屏的窗格
   就是持有它的那一个。
2. **`session:reconnect`**：与 `session:duplicate` 共用 `createFromBlueprint()`，区别只在错误
   文案和调用者。副作用是"复制一个已经结束的窗格"现在也能用（以前会报 NOT_DUPLICABLE）。
3. **渲染层**：`bindSessionToPanel()` 把"把某个窗格指向一个新会话"的记账抽成一处（原来内联在
   `addSession` 的 `if (existing)` 分支里），`reconnectEndedRef` 复用它；`TerminalPanel` 里
   `ended` 是局部状态，所以**必须在 `session` 变化时清掉**，否则重连成功后遮罩还盖在上面。

## 每项的关键决定（别轻易改）

- **内存纪律是"用到才申请"**，不是"少占内存"：工具页各自一个 chunk、按需 import、离开即卸载；
  主进程的 store/manager 全是 `??=` 的懒单例；隧道从不自动启动（启动时只恢复定义）。
  `smoke:memory` 是这条纪律的闸门：查构建产物（工具页代码不在启动 bundle 里）+ 运行时
  （打开/离开的增量和收敛）。
- **测量内存必须先强制 GC**（探针里 `--expose-gc` + 每次测量前 `window.gc()`）。不加的话每轮
  稳定 +3 MB，看着像泄漏，其实只是 V8 没回收；加了之后是 +3.0/+0.0/+0.1/+0.3。
  **"没回收"和"被留住了"是两个结论，只有后者是 bug。**
- **SFTP 默认折叠**靠的是结构而不是开关：`SectionFrame` 在 `collapsed` 时不渲染 body，
  面板根本不挂载，effect 不会跑，也就没有第二条连接。迁移老用户用的规则是"存储里没有
  `collapsed` 字段 ⇒ 跟随内置默认"——用户亲手展开过会写下 `collapsed: false`，不会被覆盖。
- **tag 筛选是 AND（多选）**：`tagFilters` 是数组，主机要同时带全部所选 tag。搜索框也搜 tag
  （tag 是大家记住一台机器的方式之一）。断言写法是"剩下的每一行都满足条件"，不是固定行数。
- **快速脚本与打字同一条规则**：只发给**在屏**的窗格。隐藏的标签页有活的 backend，但用户看不见
  它 —— 往里写命令是那个"某些窗格没收到输入"的观感的来源。
  `sendToAll()` 与 `routeInput()` 的两个刻意不同：**包含**当前窗格；收整行不收按键；多行逐行提交
  （一整块粘进 readline 会被当成一条长命令）。
- **断线重连不劫持活着的窗格**：`deadPaneFor()` 只认 `endedSessionsRef`。改这里之前先看
  `smoke/reconnect`。
- **telnet 是自己实现的字节状态机**，串口用可选依赖 `serialport`（缺了要明确报"不可用"）。
- **隧道永不自动重连**；改目标的隧道必须停掉（`sameTarget()`，改名不算改指）。
- **REST 与 S3 都走主进程**：渲染层是 `file://`，页面里 `fetch` 受 CORS 限制。渲染层自己从不碰网络。
- **S3 secret key 只留内存、不落盘**（`rememberSecret` 为真才存）；SigV4 手写，不引 AWS SDK。
- **`sanitiseTree()` 是读路径白名单**：`SavedSession` 上新加字段必须同时加进去，否则存了也会在
  重启后消失。这个坑踩过一次。

## 踩过的坑（这批新增的）

1. **`performance.getEntriesByType('resource')` 在 `file://` 下是空的**：用它查"某个 chunk 有没有
   被加载"会因为看不见而**通过**。改成查构建产物（页面 test-id 不能出现在 `index-*.js` 里）。
2. **探针自己也会被测进去**：从主进程每 150 ms 轮询一次页面是否出现，那些 `executeJavaScript`
   本身就在渲染层堆里占量。改成一次调用、等待放在页面内完成。
3. **`webContents.getProcessMemoryInfo` 在这个 Electron 版本不存在**，用 `app.getAppMetrics()`
   （字段是 KB）。
4. **PowerShell 的 here-string 拼接把脚本内容写进了源码文件**（`ipc.ts` 被塞进 `Rep "..."` 那几行）。
   教训：**改源码一律用 `edit` 工具**，PowerShell 只做只读查询和 git 操作。
5. **探针里不能有反引号和 `\d`、`\/` 这类反斜杠**（会被模板字符串吃掉）。`npm run check:probes`
   会拦（49 个文件逐个解析），改完探针立刻跑它。
6. **断言的正确性要查证**：`features3` 里"每个窗格都收到"曾失败，实际是那两个窗格堆叠、只有
   一个在屏 —— 后来发现同一套件后面印着 `visible=2 hidden=1`。**先确认断言对不对，再改代码。**
7. 时序断言用条件等待（`waitFor(条件)`），不要写死 `wait(2000)`：`smoke:reconnect` 曾因此
   偶发失败一次。
8. **打包机没有 Python**：electron-builder 默认要重建原生依赖（`@serialport/bindings-cpp`），
   node-gyp 报 "Could not find any Python installation to use"。这两个依赖是**可选依赖**且都自带
   NAPI 预编译（没有 ABI 后缀就是 NAPI，Node 与 Electron 通用），所以 `build.npmRebuild = false`。
   别只凭推理关掉它：先在 Electron 里真的 require 一次并用起来，再启动**打包后的 exe** 用 CDP 确认
   应用内部能开出本地 shell（node-pty 走 IPC）—— 两步都过了再留这个开关。
9. 探针断言**不要写恒真表达式**（`x || true`），也别写"只验证消失"的断言 —— 先决条件从未成立时它会
   静静通过（`smoke:reconnect` 就有一条是这样混过去的）。

## 第三批：断线重连保 history（`8768603`）

三个需求共用一层机制，所以一起做：

1. **重连后历史不丢、还在同一个窗格**
2. **Ctrl+R 重连**
3. **被动断开自动重试，次数与间隔可设置**（默认 3 次 / 10 秒）

| 项 | 兜底 |
| --- | --- |
| 同 id 重生、历史保留、Ctrl+R 两个方向 | `smoke:reconnect` 30/30 |
| 自动重试（挂断后自愈 / 拒连后放弃） | `smoke:transport` 19/19 |

### 决定（别轻易改）

- **重连是"重生"不是"新建"**：`SessionManager.create(..., reuseId)` 沿用原 session id。终端是按
  session id 建的，id 不变终端就不重建，滚动缓冲自然留着。改回新建 id 等于把 history 丢掉。
- **退出后不删会话记录**，只把 backend 置空。记录里的滚动缓冲（≤256KB/窗格）就是历史，窗格挂载时
  还能 replay。`list()` 只返回活的，所以"有几个会话"的语义没变；记录在窗格关闭时释放。
- **`attach()` 里的 backend 同一性判断**：被替换掉的旧 backend 迟到上报 exit 时不许影响新连接。
  没有这一条，重连成功后紧接着就会被上一条连接的退出事件打死。
- **"被动"= 不是应用要关的 + 退出码不是 0**。网络掉了、对端消失 → 退出码空 → 重试；用户敲 `exit`
  （退出码 0）、关窗格、Ctrl+D → 不重试。
- **一次掉线事件内累计次数**，连接稳定 10 秒才清零。否则"开起来就断"的传输（telnet/串口报成功只代表
  socket 开了）会无限重试，"3 次"就形同虚设。
- **重连"成功"要验活**：`reconnectSession` 返回 ok 之后还要确认会话仍在，否则会绑定一个已经死掉的
  会话，把遮罩清掉、留下没有任何说明的死终端。
- **Ctrl+R 只在已结束的窗格上生效**，活着时放行给 shell（readline 的反向搜索）。与 Ctrl+D 同一条规矩。

### 顺带修的真 bug

telnet 后端 socket 掉线时上报 `exit(0)`（假装对端正常退出），使"掉线"与"用户登出"从外部无法区分 ——
自动重试正好依赖这个区分。telnet 没有退出码，现在如实报 `null`。

## 第四批：抽屉会话区搜索（`861539c`）

需求：终端页抽屉的会话区也能搜，按 tag + name + ip。

| 项 | 兜底 |
| --- | --- |
| 名称 / 地址 / 标签搜索、无匹配提示、清除与 Esc | `smoke:drawer` 80/80 |

### 决定（别轻易改）

- **搜索在树里，不在 App 里做过滤**：`SessionTree` 收 `query` + `onQuery`，`matchesFilter()` 同时
  看标签芯片和输入框。名字、地址、标签是同一件事的三种记法，分开做会漂。
- **搜索时收起空文件夹**，没搜索时全部保留（空文件夹也是拖放目标）。这条区别是有意的：搜索要的是
  "匹配的那几台"，不是整棵树的形状。
- **`query` 放在 App 而不是 `SessionTree` 内部**：抽屉分区可以折叠、可以重排，组件一卸载查询就没了。
- 探针夹具里因此多了一台 `web-1`（`10.9.8.7` / tag `staging`）：只有一台主机时，"搜到了"和"没搜"
  看起来完全一样。

需求：vim、less 以及其它场景不要输入提示，仅在命令行处支持。

| 项 | 兜底 |

### 决定（别轻易改）

## 第七批：历史记录只收执行过的命令

用户原话："历史记录的内容逻辑好像有问题，抽屉里的历史记录，也改成记录执行成功的命令，不是记录键盘输入的。"

**证据**：真实历史文件里躺着 `-s`、`lsscn-s`、`lssc-sn-s`、`lsscsi-s` —— 全是按键拼出来的碎片。

### 决定（别轻易改）

- **永远不存按键镜像**。Tab 补全、上下键召回都不经过 `onData`，镜像必然漂移；`feed()` 里那条
  `else if (line.trim()) report(line.trim())` 的兜底就是碎片的来源，已删除。**读不出提示符终点就不
  记录**——漏一条是空白，记错一条是关于"我干过什么"的假话。
- **提示符长度要会重新测量**：每条命令执行完、提示符重绘时测一次（`sync()` 里靠 `settledPrompt()`
  判断：镜像为空 + 行非空 + 光标在行尾）。这样 `cd` 到更深目录后提示符变长也能对齐。
- **`screenTouched` 这个标记不能省**：按上下键时 shell 会把召回的那一行**当输出重绘**，形状和"重绘提
  示符"一模一样。若在那里测量，提示符终点会落在召回文本的末尾，于是只记下之后敲的字符——正是 `-s`
  的成因。所以任何转义序列都置 `screenTouched = true`，等下一次提交后才允许重新测量。
- **存储层再兜一道**（`looksExecutable`）：`-s` 这种只剩参数的、以空格开头的（shell 的"别记这条"）、
  以及还带着提示符的串一律不收；补全候选列表用同一份过滤。输入层修好了也要有这一层——UI 逻辑会改。

### 已知边界

- 没有 shell 集成（OSC 133）就**拿不到退出码**，所以"执行成功"只能做到"确实提交并执行了这一行"，
  做不到"退出码为 0"。真要做需要给本地 shell 装 prompt 钩子，SSH 远端装不了。
- `read -p "Name: "` 这类**回显但非命令行**的输入会被记成一条命令；密码提示不回显，反而因为读不到
  文本而自动不记录。

### 决定（别轻易改）

- **提示的关闭监听挂在 `document` 上用 capture**：终端里的点击会被 xterm 吃掉、不冒泡，挂在容器上收不到；
  而且"别处"包括其他窗格。判据是 `box.contains(target)` —— 按在列表上时不关，那一击是选中。
- **看门狗必须先问"网格和容器一致吗"再动手**。`dock.layout(w, h, true)` 不只是量尺寸，它会**重新分配整张
  网格**；每 100ms 调一次等于把正在拖的分隔条按回平均分（用户看到的"闪"就是这么来的）。
  判据来自 DOM：`Gridview.layout()` 会把量到的尺寸写成 `.dv-grid-view` 的内联样式，所以"不一致"可以直读。
  它要防的那个故障（网格卡在挂载时的 100×100 占位）读出来正是"不一致"，照样会被修正。
- **手势进行中绝不插手**（`fitsArePaused()`），即使尺寸对不上 —— 拖拽中重排会把指针下的分隔条挪走。
- **这类回归只能从渲染层外面测**：`smoke:gesture` 用 CDP 的 `Input.dispatchMouseEvent` 真拖，边拖边读两个
  分组的宽度。只看拖动结束后的 DOM 是看不出"闪回"的。

## 第九批：快捷指令的颜色与合并分组

用户原话：①"快捷指令支持自定义颜色，颜色就显示在按钮框框的下面一条，好看一点明显一点"；
②"左侧的分组名称合并成一个吧，默认全部，点开可以勾选"。

| 项 | 兜底 |
| --- | --- |
| 颜色存得住、按钮上真的画出色带、没颜色的不画 | `smoke:snippet` 34/34 |
| 分组只有一个控件、默认"全部"、勾选可多选、点外面收起 | `smoke:snippet` 34/34 |
| 分组从标签改成勾选之后，ui2 的旧用例也改过来了 | `smoke:ui2` 57/57 |

### 决定（别轻易改）

- **颜色是按钮内下沿 3px 的实色条，不是给按钮染色**。这个尺寸下 3px 实色最清楚；整块染色要够显眼就会跟
  文字抢对比度。`overflow: hidden` 让色条跟着圆角走，`padding-bottom: 8px` 让文字离开色条 —— 少了这条
  颜色就成了穿过文字的删除线。
- **颜色只接受 `#rrggbb`**（`normaliseColor`），否则当没设置：一条随便什么字符串最后会变成浏览器不认识
  的背景值，画不出来也不会报错。
- **分组是一个控件 + 勾选清单，不再是一排标签**：标签把整个左端占满，而那些名字通常不是要找的东西。
  清单向上弹（栏在窗口底部），按在清单外或 `Esc` 收起。
- **多选是相加**：勾两个分组就是两组的并集；全不勾等于"全部"（`activeGroups` 为空即不过滤）。
  勾了的分组被删掉后**忽略而不是清除**，免得那组回来时筛选范围悄悄变宽。
- **重排分组从"拖到标签上"改成右键菜单里的「移到 <分组>」**，并且"未分组"永远是可选目标 —— 把一条
  指令拿出分组不该取决于当前有没有别的未分组指令。这条替换掉了旧能力，`smoke:ui2` 的旧断言语义也跟着
  改了（`ungroup` → `move:<group>`）。

## 第十批：双击选词不带分隔符、三击复制整行带换行

用户原话：①"双击选择 session 某个单词的时候，会把单词后面的 `:` 也拷贝下来……希望不要带后面的分隔符"；
②"实现三击单词可以复制一行，并且带换行"。

| 项 | 兜底 |
| --- | --- |
| 双击只选词（不含冒号）、三击选整行、复制带换行、普通选词不带换行 | `smoke:features` 104/104 |

### 决定（别轻易改）

- **分词符是 `wordSeparator`，不是复制时修剪**。xterm 默认只把括号和引号当分隔符，冒号因此算单词的一部分。
  在 `buildTerminalOptions` 里换成 ` ()[]{}',"` + 反引号 + `:,;`。**没有加 `=`**：它更多是 token 内部
  （`--flag=value`）而不是词尾。代价是 `http://x` 双击会断在冒号处 —— 这是用户明确要的取舍方向。
- **换行是"三击那次复制"的属性，不是"整行选择"的通用属性**。xterm 不回报点击次数，所以在
  `useTerminal` 的 mousedown 里记 `event.detail >= 3`（xterm 自己也是靠 detail 分派的），存进 registry，
  由 `selectionTextFor()` 在复制时消费：**2 秒窗口**（`LINE_SELECTION_WINDOW_MS`），且任何 `detail < 3`
  的按下都会立刻清掉。没有这两条，两分钟后的普通拖选也会莫名多一个空行。
- **两条复制路径共用同一个入口**：选中即复制走 `selectionTextFor`，`Ctrl+Shift+C` 也先问它、拿不到才退回
  `window.getSelection()`（那一条是给"在抽屉里选字"用的）。只改一条会得到"有时候带换行有时候不带"。
- 三击选整行本身是 **xterm 自带**的（`_handleTripleClick` → `_selectLineAt`），不需要自己实现。

## 第十一批：主机标签保存不上

用户原话："hosts tag 添加好像有问题，保存不上内容"。

**复现**（先复现再改，这是关键）：打开主机编辑器 → 输入 `alpha` 回车 → 再输入 `beta`（**不回车**）
→ 点保存 → 存进去的是 `["alpha"]`，`beta` 没了。

**原因**：标签输入框只在回车/逗号时提交（`addTag`），而 `submit` 读的是已经提交的 `tags` state。最常见的
操作顺序（敲完就去点保存）正好落在这个缝里，而且**没有任何提示**。

### 决定（别轻易改）

- **提交时把输入框里的内容折进去**（`tagsForSave()`），一次性算好再交给两条保存路径（单条 / 批量导入）。
  只在一处折叠，两条路径就不可能对"标签是什么"有分歧。
- 不用"失焦即提交"来兜：那会让"点一下别的字段"也变成提交动作，比现在的显式行为更难预测。
- 探针里那条新断言就是照着这条路写的：**只输入、不回车、直接保存**，然后断言主机行上出现该标签。
  它在修复前会失败 —— 也就是说这个 bug 之前没有任何保护。

## 第十二批：文件传输的独立进度窗口

用户原话："文件上传下载 单独有个窗口何以查看进度"。

**做之前的样子**：`downloadFile` / `uploadFile` 就是 `read.pipe(write)` 然后等结束，**没有任何进度**，也没有
任何全局清单；SFTP 面板只能报它当前看着的那个会话，离开面板就看不见了。

### 决定（别轻易改）

- **传输清单位于主进程**（`src/main/transfers.ts`），不在渲染进程。窗口可以**在传输中途打开**，那时它必须
  显示真实状态，而不是"渲染进程恰好看到过的那部分"。窗口打开时先 `listTransfers()` 再订阅 `transfer:changed`，
  少了第一次拉取就会对着一个正在传的文件显示空列表。
- **进度节流 200ms，但合并而不是丢弃**：节流窗口内到达的字节必须跟着下一次广播一起出去，否则进度会停在
  最后一次被允许广播时的百分比。
- **取消是一种结局，不是错误**：取消就是销毁两个流，而销毁后的流看起来和正常结束一模一样，所以
  `finishTransfer` 遇到 `cancelled` 不改写状态，并且 `endTransfer` 给调用方返回 `{ok:false, cancelled:true}` ——
  否则面板会弹"上传成功"，而文件只有一半。
- **`sftp.ts` 里等的是"哪个先到"**（`settled()`：end / close / error），不是只等 `end`：被销毁的流永远不发
  `end`，只等它会让 Promise 永远挂着，窗口上就留下一个永远不会结束的任务。
- **速度/ETA 在窗口里算**（两次读数差分 + 平滑），不由主进程发：它们是"观察"的属性，窗口关着的时候发它们
  没有意义，而且发过去的值窗口还得再推导一次才对得上。
- **原生文件对话框只是前端**：传输本身走 `transfer:upload` / `transfer:download`（路径已知），
  `sftp:upload` / `sftp:download` 只是先弹对话框再调它们。这样探针能真跑传输 —— 也顺便给将来的拖放留了口子。
- 快捷键 `Ctrl+Shift+J`（`openTransfers`，builtin，可在设置里改）。

### 当前状态（第十二批之后）

- 全量闸门 **EXITCODE=0**：41 套件、0 条 `FAIL`；`smoke:drawer` 103。
- 发行说明见 `docs/发行说明-v1.5.0.md`。

## 第十三批：传输进度改成横条（按钮找不到）

用户反馈："下载上传弹窗的按钮没有看到，优化一下" —— 要求做成快捷指令上方的一条横向任务栏：可展开、可关闭、
保留历史、一键全部清除。

**结论（记下来免得再犯）**：上一版把进度放进窗口，入口是 SFTP 面板里五个图标中的一个，只有面板正好开着才
看得见。**功能是否找得到，和功能是否存在一样重要。**

### 决定（别轻易改）

- **新任务必须能自动展开横条**，不能只靠"横条出现"来宣告：横条通常已经存在（它保留历史），所以"出现"不是
  一个可用的信号。折叠/展开由 `TransferBar` 里"运行中集合出现了新 id"驱动。
- **✕ 只是隐藏**（`transferStripHidden`），传输继续；App 里同一个"新任务"信号把它重新显示出来。少这一条，
  关一次就再也看不到进度。
- **⌫ 只清已完成的**：把进行中的从列表里删掉会留下一个没人能取消的传输（`clearFinishedTransfers` 的语义）。
  清空后横条自己消失。
- **横条与窗口共用行渲染**（`TransferList` + `useTransferSpeeds`）：两个界面各写一套"传输长什么样"，改一处、
  另一处不动，很快就会不一致。
- 横条在 `!focusMode` 且 `transfers.length > 0` 时渲染，因此**只占布局高度、不覆盖终端**（几何断言守着这条）。
