## 铁律（每条都踩过）

| 事 | 做法 |
| --- | --- |
| 验证 | 第三十批起分级：**日常**先定向 `npm run verify:fast -- --only <套件>`（四项检查照跑，见该批小节）；**推 origin 前** `npm run verify:fast` 全量；**发版/打标签前**原版 `npm run verify`（先清 `node_modules\.smoke-data`，要求 **EXITCODE=0 且 0 条 FAIL**）。共享层改动（`src/shared/`、`src/main/store`、preload、ipc、`App.tsx`、i18n 机制）**不许定向跑**，老实全量。偶发失败先单独重跑该套件再定性 |

| 提交 | 中文，`修复:` / `新增:` / `改进:` / `文档:` / `发布:`。一次功能一个提交，文档与版本号单独一个 |
| 发布 | 版本号 → 文档 → `npm run dist:win` + `npm run pack:zip` → 打包版自检（`release/win-unpacked` 里跑一段 CDP）→ `SHA256SUMS-<版本>.txt` → 分支 `release/v<版本>` + 标签 `v<版本>` 停在**构建提交**上 → 推 origin |
| 产物 | `release/` 已 gitignore。清理按用户口径：**只留当前版本 + 上一版** |
| 源码编辑 | 不要用 PowerShell `.Replace` 改 JSX/TSX（会把代码写坏），用 `edit` / `write` 工具 |
| 本机环境 | 受限沙箱下 `npm run build` / `check:probes` 会因 esbuild / `spawnSync` 的管道 stdio 报 `EPERM` —— 那是环境限制，不是项目问题，换非受限权限跑即可 |

## 容易被改错的地方（按主题索引，细节在对应批次）

- **dockview**：主题变量会被内层 `.dv-shell` 重新声明，覆盖要同时命中所有带主题类的元素（第十四批）；
  面板参数 `addPanel` 时不落盘，必须 `updateParameters`，`fromJSON` 之后 `getParameters()` 是空的（第十二批）。
- **快捷键**：作用在**当前活动面板**上；xterm 会 `stopPropagation`，分发器必须用捕获阶段（第十五批）；
  探针里要点「活动面板」得用 `__tdDockApi` 的 `setActive`，点标签不一定够（第十六批）。
- **重连**：两条路——会话结束走 `reconnectEndedRef`，从布局恢复走 `reconnectRef`（按保存的主机），
  判据是面板参数 `disconnected === true && savedSessionId`（第十六批）。
- **传输**：`pump()` 固定并发，块必须按自身偏移写；中止在块之间检查（`fastGet` 的 `step` 返回值在 ssh2 1.17 里
  被忽略，不能用它做取消）；测试链路本身被限速，速度别拿本机测（第十五批）。
- **存储文件**：一个文件只能有一个写者（REST 历史交给渲染进程写）；`ref` 必须与 `state` 同步更新，
  否则连发会丢条目（第十七批）。
- **探针陷阱**：断言要等"这一次的结果"，别等"屏幕上有错误"（上一步留下的还在）（第十七批）。
- **探针陷阱 2**：`upsertSession` / `upsertFolder` 返回的是**整棵树**，不是刚建的那个对象 —— `.id` 恒为
  `undefined`，用它的选择器全部落空，看起来像"功能没生效"。**种数据一律按名字回读**（第二十、二十一批
  各踩一次）。另外：功能缺失的分支要写**显式 FAIL**，别让断言被 `if` 悄悄跳过（第二十一批）。
- **探针陷阱 3**：探针中途离开又回到工具页（比如 rest.cjs 第 6e 节验证高度时去了一趟 S3 页），
  页面是**重挂载**的 —— 之前抓的元素引用全是从文档上摘下来的死节点，点死节点不报错也不触发 React，
  后面就"查不到元素"或"点了没反应"。回页之后要用到的元素**按现状重新查**（第二十九批踩一次）。
- **探针陷阱 4**：`executeJavaScript` 的脚本体是外层模板字符串，里面写的 `'\r\n'` 会被外层
  **先转义成真实换行**嵌进内层单引号串 → `SyntaxError: Invalid or unexpected token`，而且是
  到浏览器里才炸，`node --check` 看不出来。转义一律 `String.fromCharCode(13,10)`、
  ESC 用 `String.fromCharCode(27)`（第三十二批踩一次）。
- **工具陷阱：PowerShell 与这份仓库里的 UTF-8 中文文档**。这台机器的 PowerShell 用
  `Get-Content`/`Set-Content` 默认按 **ANSI（GBK）** 读，UTF-8 的中文读进来就是乱码，
  再写回去就是**双重编码**（`## 第三十一批` 变成 `## 绗笁鍗佷竴鎵癸細`）。要么显式
  `Get-Content -Encoding utf8` + `[System.IO.File]::WriteAllLines($p, $lines, [System.Text.UTF8Encoding]::new($false))`，
  要么**直接用编辑工具改文档**（首选）。踩过一次，靠 git 恢复（第三十三批）。
- **凭据是 IPC 层的事，store 不碰密文**：删主机要 `getCredentials().remove(id)`，复制主机要把密文用新 id
  重新封一遍（`duplicateSessions` 返回 `{ sourceId, id }` 对给 IPC 用）—— 少了后者，复制出来的主机连不上
  （第二十一批）。
- **批量操作一律"一次 IPC + 一次 commit"**：折叠全部（第二十批）、批量删除/复制/移动（第二十一批）都是。
  在渲染层循环单台接口 = N 次写盘 + N 次广播 + N 次重绘，列表会一边点一边抖。
- **勾选/选中是临时状态**：主机页的勾选放页面内 `useState`，不做持久化；批量操作做完就清空。别"为了
  体验"把它存进 `layout.json`（第二十一批）。
- **重连是后台动作，不许抢焦点**：`bindSessionToPanel(..., activate=false)`。自动重连成功时若调
  `setActive()`，用户正在敲的那个节点会被拽走（第二十二批，用户明确抱怨过）。
- **切换窗格要把键盘交给新窗格**（第二十七批）：规则在 `src/renderer/src/components/focusPolicy.ts`
  （纯函数），由 `App.tsx` 的 `handKeyboardRef` 执行。两个必须记住的点：①**终端的
  `xterm-helper-textarea` 本身就是 textarea**，规则里必须先判 "是不是终端" 再判 "是不是可编辑"，
  否则"壳里打字时键盘切窗格"这条唯一本来正确的路会被自己废掉；②**侧栏 `.td-sidebar` 不是模态**，
  它只是常驻面板 —— 点侧栏会话行必须把键盘交给终端；真正拦焦点的模态是
  `.td-modal / .td-drawer / .td-lock`（`.td-drawer` 是全屏 `fixed` 层，点连接窗口里的连接时
  抽屉还挂着，那条路要 `force` 显式交接）。
- **PTY 尺寸：blueprint 必须跟着 `session:resize` 更新**，渲染端重连时还要 `resendSize()` 无条件再推一次
  —— 渲染端"尺寸没变就不发"的判断遇上重连（窗格没变、后端是新的）会永远不发，全屏程序就只画半屏
  （第二十二批）。
- **重连失败只在窗格自己的遮罩上说**（`reconnect-error`），**不弹全局 `connect-alert`**：重连可能是
  应用在用户没看那个窗格时自己做的（第二十二批）。
- **探针陷阱 3**：dockview 会**卸载隐藏的 tab**，所以"历史还在不在"要读 `term.buffer.active`
  （`getLine(i).translateToString(true)`），不能读 `.xterm-rows`（只有视口）；而且重连回来的 shell
  **自己会清屏**（cmd 启动即擦屏），"屏幕上还有旧内容"不是应用能保证的事（第二十二批）。
- **高亮只能是颜色**：xterm 的 decoration 只支持前景/背景（`#RRGGBB`），没有加粗/下划线（第二十三批）。
- **别把高亮做成注入转义序列**：会把列宽/折行/光标搞错，还会污染复制内容（第二十三批）。
- **设置项别嵌套**：`terminal` 是浅合并，嵌套对象会被整体替换、丢掉同级字段；要加校验就写
  `mergeXxx`（第二十三批的 `mergeTerminal`）。
- **探针里连 `\\s` 都不许有**：`scripts/checkprobes.cjs` 会把模板字符串里的 `\s` 当错误
  （"eaten by the template literal"），正则要换成 `split(' ').join('')` 这类无转义写法（第二十三批）。
- **改默认键位必须带迁移**：存量存盘里是旧值，只改 `DEFAULT_KEYBINDINGS` 对已装机器无效；
  照 `RETIRED_BINDING_DEFAULTS` 的模子，**只在值恰好等于旧默认时**改写（第二十四批）。
- **别用 `defaultPrevented` 判断"按键有没有被应用吃掉"**：xterm 对自己转发的键也会 preventDefault，
  永远为真。要看**终端数据通道有没有吐出那个字节**（第二十四批的 `smoke:keys`）。
- **版本号别用 `app.getVersion()`**：指向脚本启动时（探针、dev）它是 Electron 的版本；
  用 `ipc.ts` 的 `appVersion()`（找 package.json + 包名校验）（第二十四批）。
- **不要把新功能的控件藏在开关后面**：默认关的功能只在打开后才露出选项，用户会当它没做
  （第二十五批，用户就是这么反馈的）。要藏就藏"值"，别藏"能力"。
- **也不要把它们置灰禁用**：同一个功能连错两版的教训 —— 选项要**一直可见、一直可改**，
  总开关只管"应用"（第二十五批追加）。
- **总开关必须和它管的选项在同一块里**，而且**动选项就等于开总开关**：分开放、默认关，
  用户配完会以为功能坏了（第二十五批第三次追加）。
- **设置是"改草稿 → 点保存"**：未保存一定要显眼（底部操作栏吸底 + 未保存提示），
  否则用户改完看不到效果，报"没生效"。别把"要保存"这件事留成静默的坑。
- **工具页的"整页中文"不是补词表就完了**：页面上有三类文案不走 `t()` —— 共享数据（REST 的模板名/说明，按 id
  计算键）、主进程决定的错误（`RestResponse.errorCode`；Node 报的原始错误不给码、照原样显示）、硬编码兜底。
  少了任何一类就是"半中半英"，而 `check:i18n` 抓不到（缺翻译只是 note）（第十八批）。
- **`check:i18n` 的计算键前缀可以带点**，且必须写成整段字面量：`t('restpage.err.' + code, english)` 只豁免
  `restpage.err.*`；写成 `t('restpage.' + ...)` 会把整页放行，闸门等于废掉（第十八批）。
- **`smoke:i18n` 是"整页中文"的闸门**：判据是"这些英文一个都不许出现"，不是"页面里有中文"。新增工具页翻译时
  照 REST 那 11 条的样子加（第十八批）。
- **REST 请求头有两个编辑器、一份数据**（第二十八批）：规则在 `src/shared/restHeaders.ts`，
  页签切换靠 `headersJsonForRef`（"JSON 框上次与行一致时的行签名"）。**不要**改回"每次点 JSON 都从行重写"：
  没解析成功的文本是唯一的一份，重写就是用户报的"切换之后之前写的就没有了"。单引号的对象字面量是
  **翻译引号后仍然过 `JSON.parse`** 才收的 —— 别换成 eval / 宽松解析器，那会把 `{ 'X-Broken': }`
  变成一条少了的认证头。
- **REST 请求体的高度存的是"拖拽"，不是"布局"**（第二十八批）：`RestState.bodyHeight` +
  `clampRestBodyHeight`（`src/shared/restLayout.ts`）。页面上只在该元素有**内联 `style.height`** 时才
  回读 —— 那是原生 resize 手柄留下的唯一痕迹；少了这个判断，窗口尺寸一变就会把用户拖出来的高度覆盖掉。
  加字段照样要改 `RestStore.sanitise`（硬白名单），而且**三个** `saveRestState` 调用点都要带上它。
- **主机页的折叠态是 `layout.json` 的 `hostsFolded`（按分组 key），不是抽屉的 `SessionFolder.expanded`**：
  同一棵文件夹树的两个视图各有用途，在管理页收起二十个分组不该把终端页的抽屉也收起来；而且用
  `folder.expanded` 要把"全部折叠"变成对每个分组各写一次盘（第十九批）。
- **`LayoutState` 加字段必须同时改 `LayoutStore.sanitise`**：那是硬白名单，漏了不会报错、只会**静默消失**
  （与 `sanitiseTree` 同一个坑）。`hostsFolded` 只留字符串项，非法项会让那个分组永远折不上（第十九批）。
- **筛选必须压过折叠**：搜索或标签筛选一生效，折叠全部失效、折叠按钮也不画 —— 否则"筛出来了却看不见"
  会被读成"这台主机没了"（第十九批）。**两个页面同一条规矩**：会话树（抽屉）也一样，而且是先有 bug 后补的
  （第二十批）。
- **会话树（抽屉）与主机页的折叠是两套模型**：抽屉用 `SessionFolder.expanded`（跟着分组存、逐个 `saveFolder`），
  主机页用 `layout.json` 的 `hostsFolded`。别"统一"成其中一个 —— 理由见第十九批（同一棵树两个视图两种用途）
  与第二十批（抽屉里那个是分组的属性，跟着树走）。
- **"全部折叠"要走一次 IPC + 一次 commit**：`SessionStore.setAllFoldersExpanded`。在渲染层循环调
  `saveFolder` 会变成 N 次写盘 + N 次广播 + N 次重绘（二十个分组就是二十次），列表会一边点一边抖
  （第二十批）。
- **平台差异一律走 `src/shared/platform.ts` 的纯函数**（注入平台参数），别再写 `process.platform` 的
  内联分支：那是唯一能在 Windows 上判对错的写法。`DEFAULT_SETTINGS` 只是渲染端的占位，
  真正的默认值由 `defaultSettings(platform)` 给（主进程 `Stores.mergeSettings` 用）。
- **mac 的应用菜单不能占 `Cmd+W`**，那是"关闭当前窗格"；系统关窗挪到 `Cmd+Shift+W`。
  菜单里**不要用 `role:'quit'`** —— 它直接 `app.quit()`，会绕过渲染端的退出确认，而 `before-quit`
  又会先把所有会话拆掉（所以那里加了 `isQuitting()` 门控）。Edit 菜单的 role 是 mac 上
  `Cmd+C/V/X/A/Z` 的**唯一来源**，删了就没复制粘贴。
- **打包必须按架构分 runner**：`build.npmRebuild` 是 false，`@lydell/node-pty` / `serialport`
  按架构装可选依赖包，一个 job 只能打出它装依赖时那个架构的包（CI 用 `macos-15` + `macos-15-intel`）。
- **mac 的键位是一张逐条决定的表**（`MAC_BINDING_DEFAULTS`），不是"把 Ctrl 换成 Meta"。
  新增一个 binding 必须同时在表里加一行 —— 探针会查覆盖率，漏了会 FAIL（否则会悄悄回退到机械换法）。
  参照的是 iTerm2 / Terminal.app 的真实手势（`Cmd+C/V`、`Cmd+Shift+[/]`、`Ctrl+Cmd+F`、`Cmd+数字`）。
- **迁移表是"每个 id 一组规则"**（`retiredBindingDefaults` 返回 `{from,to}[]`）：Windows 的旧默认、
  以及**上一版 mac 的旧默认**都要覆盖，但只改写"恰好等于旧默认"的值。别把 Windows 的规则预置进
  darwin 表 —— 那样 `Ctrl+W` 会命中"解绑"而不是"→ `Cmd+W`"（踩过，探针抓出来的）。
- **存储用 `Meta`、显示用 `Cmd`**：任何把键位显示给用户的地方（抽屉提示、重连提示、设置列表、
  冲突提示）都要过 `displayChord(键位, 平台)`，否则 mac 用户会看到 `Meta+R` 这种话。
- **`Cmd+C` / `Cmd+V` 在输入框里要交回系统**（`isNativeEditTarget`）：它们是 mac 上系统的复制粘贴，
  应用只在焦点位于终端时接手，否则设置里的每个输入框都按不了复制。
- **CI 里探针和打包是两个独立 job**：v2.1.0 因为探针红了而**丢掉了 mac 产物**（打包被跳过）。
  现在探针失败只会让 `probe` job 红，`package` 照出 dmg/zip，失败的检查项以 `::error::` 注解挂出来。

## 第二十三批：输出高亮 + 复制保持纯文本（v1.12.0）

需求原话：「尝试一下 重点关键词 或者 ip 什么 的 这种信息 添加配色方案，类似 oh-my-zsh 那种 颜色 方案

### 实现选型（这是重点，别改成注入 SGR）

**用 xterm 的 decoration 给单元格上色，绝不往数据流里塞 ANSI。** 若改成"把匹配包上颜色码再写进终端"：
列宽计算、折行、光标位置全错，而且颜色码会顺着复制/粘贴流到下游 —— 正是需求里要避免的。
现在的代价是 decoration 只能染前景/背景（`#RRGGBB`），没有加粗/下划线，配色方案只能是颜色。

### 两个必须知道的 xterm 事实

1. **颜色不在 decoration 元素上**。DOM 渲染器把 decoration 的颜色烘焙进**行内 span**，
   而且**一个字符一个 span**；`.xterm-decoration` 那个 div 只有位置和宽高、背景透明。
   所以"验证颜色"要读那些 span 的 `getComputedStyle`，而**带某配色的 span 个数 = 匹配长度**
   （这是探针的核心断言手法：`runCount(runs, bg, fg) === 11`）。
2. decoration 的 `layer: 'bottom'` 放在选区下面，选中高亮文本仍然看得出被选中。

### 设置项放平（浅合并的坑）

`mergeSettings` 对 `terminal` 是**浅合并**，嵌套对象会被整体替换并丢掉同级字段。所以三个高亮字段是平铺的
（`highlightEnabled` / `highlightScheme` / `highlightRules`），并补了 `mergeTerminal`：
未知的规则 id 丢掉；**列表缺失 = 用默认值**，不能理解成"一条都不开"（否则开关打开却什么都不亮）。

### 复制的保证（以及一个已确认的事实）

缓冲区里的文本一个字节都没改，所以复制/复制整屏/保存输出/导出都是远端原样文本、无 ESC/OSC。
探针里断言了这一点。顺带确认：**折行的长行复制回来仍然是一行**（xterm 不在折行处插换行），
这条以前没人钉住，现在有断言了。

### 探针（新套件 `smoke:highlight`，16 条，并进闸门）

一个本地 shell，不需要网络。旧代码上 16 条里 **7 条 FAIL**。断言的是 DOM 里的真实证据：
decoration 的**几何**（每个匹配按自己的长度成框：IP 11 格、error 5 格、链接 20 格）、
**行内 span 的配色与个数**、逐条规则开关、总开关，以及复制文本里没有 ESC。

## 第二十二批：重连改后台 + vim 半屏的真因（v1.11.1）

需求原话：「session重连 机制 在后台做就行，失败或者成功 不用下方红色弹窗，也不用窗口自动弹出来，

### 两个真因（别改回去）

- **抢焦点**：`bindSessionToPanel` 无条件 `panel.api.setActive()`，而自动重连也走它。现在多了
  `activate` 参数，重连传 `false`。**不要**为了"让重连的窗格显眼一点"再加回来。

  - 渲染端 `useTerminal.resendSize()`（`resendPending` 标志 + `doFit`），会话对象被替换时无条件推一次。

### 失败提示的规矩

## bug 9 的三处改动（一个 bug 三处才修得动）

1. **主进程在会话退出后保留蓝图**（`session:exit` 不再 `blueprints.delete`）。蓝图是这个窗格
   "怎么连上去的"唯一记录：主机、凭据、私钥、端口。没有它，一个 quick connect 断掉之后
   Reconnect 无从下手。释放点在 `session:close`（窗格关掉时），所以不会累积 —— 在屏的窗格
   就是持有它的那一个。
2. **`session:reconnect`**：与 `session:duplicate` 共用 `createFromBlueprint()`，区别只在错误
   文案和调用者。副作用是"复制一个已经结束的窗格"现在也能用（以前会报 NOT_DUPLICABLE）。
3. **渲染层**：`bindSessionToPanel()` 把"把某个窗格指向一个新会话"的记账抽成一处（原来内联在
   `addSession` 的 `if (existing)` 分支里），`reconnectEndedRef` 复用它；`TerminalPanel` 里
   `ended` 是局部状态，所以**必须在 `session` 变化时清掉**，否则重连成功后遮罩还盖在上面。

## 每项的关键决定（别轻易改）

- **内存纪律是"用到才申请"**，不是"少占内存"：工具页各自一个 chunk、按需 import、离开即卸载；
  主进程的 store/manager 全是 `??=` 的懒单例；隧道从不自动启动（启动时只恢复定义）。
  `smoke:memory` 是这条纪律的闸门：查构建产物（工具页代码不在启动 bundle 里）+ 运行时
  （打开/离开的增量和收敛）。
- **测量内存必须先强制 GC**（探针里 `--expose-gc` + 每次测量前 `window.gc()`）。不加的话每轮
  稳定 +3 MB，看着像泄漏，其实只是 V8 没回收；加了之后是 +3.0/+0.0/+0.1/+0.3。
  **"没回收"和"被留住了"是两个结论，只有后者是 bug。**
- **SFTP 默认折叠**靠的是结构而不是开关：`SectionFrame` 在 `collapsed` 时不渲染 body，
  面板根本不挂载，effect 不会跑，也就没有第二条连接。迁移老用户用的规则是"存储里没有
  `collapsed` 字段 ⇒ 跟随内置默认"——用户亲手展开过会写下 `collapsed: false`，不会被覆盖。
- **tag 筛选是 AND（多选）**：`tagFilters` 是数组，主机要同时带全部所选 tag。搜索框也搜 tag
  （tag 是大家记住一台机器的方式之一）。断言写法是"剩下的每一行都满足条件"，不是固定行数。
- **快速脚本与打字同一条规则**：只发给**在屏**的窗格。隐藏的标签页有活的 backend，但用户看不见
  它 —— 往里写命令是那个"某些窗格没收到输入"的观感的来源。
  `sendToAll()` 与 `routeInput()` 的两个刻意不同：**包含**当前窗格；收整行不收按键；多行逐行提交
  （一整块粘进 readline 会被当成一条长命令）。
- **断线重连不劫持活着的窗格**：`deadPaneFor()` 只认 `endedSessionsRef`。改这里之前先看
  `smoke/reconnect`。
- **telnet 是自己实现的字节状态机**，串口用可选依赖 `serialport`（缺了要明确报"不可用"）。
- **隧道永不自动重连**；改目标的隧道必须停掉（`sameTarget()`，改名不算改指）。
- **REST 与 S3 都走主进程**：渲染层是 `file://`，页面里 `fetch` 受 CORS 限制。渲染层自己从不碰网络。
- **S3 secret key 只留内存、不落盘**（`rememberSecret` 为真才存）；SigV4 手写，不引 AWS SDK。
- **`sanitiseTree()` 是读路径白名单**：`SavedSession` 上新加字段必须同时加进去，否则存了也会在
  重启后消失。这个坑踩过一次。

## 踩过的坑（这批新增的）

1. **`performance.getEntriesByType('resource')` 在 `file://` 下是空的**：用它查"某个 chunk 有没有
   被加载"会因为看不见而**通过**。改成查构建产物（页面 test-id 不能出现在 `index-*.js` 里）。
2. **探针自己也会被测进去**：从主进程每 150 ms 轮询一次页面是否出现，那些 `executeJavaScript`
   本身就在渲染层堆里占量。改成一次调用、等待放在页面内完成。
3. **`webContents.getProcessMemoryInfo` 在这个 Electron 版本不存在**，用 `app.getAppMetrics()`
   （字段是 KB）。
4. **PowerShell 的 here-string 拼接把脚本内容写进了源码文件**（`ipc.ts` 被塞进 `Rep "..."` 那几行）。
   教训：**改源码一律用 `edit` 工具**，PowerShell 只做只读查询和 git 操作。
5. **探针里不能有反引号和 `\d`、`\/` 这类反斜杠**（会被模板字符串吃掉）。`npm run check:probes`
   会拦（49 个文件逐个解析），改完探针立刻跑它。
6. **断言的正确性要查证**：`features3` 里"每个窗格都收到"曾失败，实际是那两个窗格堆叠、只有
   一个在屏 —— 后来发现同一套件后面印着 `visible=2 hidden=1`。**先确认断言对不对，再改代码。**
7. 时序断言用条件等待（`waitFor(条件)`），不要写死 `wait(2000)`：`smoke:reconnect` 曾因此
   偶发失败一次。
8. **打包机没有 Python**：electron-builder 默认要重建原生依赖（`@serialport/bindings-cpp`），
   node-gyp 报 "Could not find any Python installation to use"。这两个依赖是**可选依赖**且都自带
   NAPI 预编译（没有 ABI 后缀就是 NAPI，Node 与 Electron 通用），所以 `build.npmRebuild = false`。
   别只凭推理关掉它：先在 Electron 里真的 require 一次并用起来，再启动**打包后的 exe** 用 CDP 确认
   应用内部能开出本地 shell（node-pty 走 IPC）—— 两步都过了再留这个开关。
9. 探针断言**不要写恒真表达式**（`x || true`），也别写"只验证消失"的断言 —— 先决条件从未成立时它会
   静静通过（`smoke:reconnect` 就有一条是这样混过去的）。

## 第三批：断线重连保 history（`8768603`）

三个需求共用一层机制，所以一起做：

1. **重连后历史不丢、还在同一个窗格**
2. **Ctrl+R 重连**
3. **被动断开自动重试，次数与间隔可设置**（默认 3 次 / 10 秒）

| 项 | 兜底 |
| --- | --- |
| 同 id 重生、历史保留、Ctrl+R 两个方向 | `smoke:reconnect` 30/30 |
| 自动重试（挂断后自愈 / 拒连后放弃） | `smoke:transport` 19/19 |

### 决定（别轻易改）

- **重连是"重生"不是"新建"**：`SessionManager.create(..., reuseId)` 沿用原 session id。终端是按
  session id 建的，id 不变终端就不重建，滚动缓冲自然留着。改回新建 id 等于把 history 丢掉。
- **退出后不删会话记录**，只把 backend 置空。记录里的滚动缓冲（≤256KB/窗格）就是历史，窗格挂载时
  还能 replay。`list()` 只返回活的，所以"有几个会话"的语义没变；记录在窗格关闭时释放。
- **`attach()` 里的 backend 同一性判断**：被替换掉的旧 backend 迟到上报 exit 时不许影响新连接。
  没有这一条，重连成功后紧接着就会被上一条连接的退出事件打死。
- **"被动"= 不是应用要关的 + 退出码不是 0**。网络掉了、对端消失 → 退出码空 → 重试；用户敲 `exit`
  （退出码 0）、关窗格、Ctrl+D → 不重试。
- **一次掉线事件内累计次数**，连接稳定 10 秒才清零。否则"开起来就断"的传输（telnet/串口报成功只代表
  socket 开了）会无限重试，"3 次"就形同虚设。
- **重连"成功"要验活**：`reconnectSession` 返回 ok 之后还要确认会话仍在，否则会绑定一个已经死掉的
  会话，把遮罩清掉、留下没有任何说明的死终端。
- **Ctrl+R 只在已结束的窗格上生效**，活着时放行给 shell（readline 的反向搜索）。与 Ctrl+D 同一条规矩。

### 顺带修的真 bug

telnet 后端 socket 掉线时上报 `exit(0)`（假装对端正常退出），使"掉线"与"用户登出"从外部无法区分 ——
自动重试正好依赖这个区分。telnet 没有退出码，现在如实报 `null`。

## 第七批：历史记录只收执行过的命令

用户原话："历史记录的内容逻辑好像有问题，抽屉里的历史记录，也改成记录执行成功的命令，不是记录键盘输入的。"

**证据**：真实历史文件里躺着 `-s`、`lsscn-s`、`lssc-sn-s`、`lsscsi-s` —— 全是按键拼出来的碎片。

### 决定（别轻易改）

- **永远不存按键镜像**。Tab 补全、上下键召回都不经过 `onData`，镜像必然漂移；`feed()` 里那条
  `else if (line.trim()) report(line.trim())` 的兜底就是碎片的来源，已删除。**读不出提示符终点就不
  记录**——漏一条是空白，记错一条是关于"我干过什么"的假话。
- **提示符长度要会重新测量**：每条命令执行完、提示符重绘时测一次（`sync()` 里靠 `settledPrompt()`
  判断：镜像为空 + 行非空 + 光标在行尾）。这样 `cd` 到更深目录后提示符变长也能对齐。
- **`screenTouched` 这个标记不能省**：按上下键时 shell 会把召回的那一行**当输出重绘**，形状和"重绘提
  示符"一模一样。若在那里测量，提示符终点会落在召回文本的末尾，于是只记下之后敲的字符——正是 `-s`
  的成因。所以任何转义序列都置 `screenTouched = true`，等下一次提交后才允许重新测量。
- **存储层再兜一道**（`looksExecutable`）：`-s` 这种只剩参数的、以空格开头的（shell 的"别记这条"）、
  以及还带着提示符的串一律不收；补全候选列表用同一份过滤。输入层修好了也要有这一层——UI 逻辑会改。

### 已知边界

- 没有 shell 集成（OSC 133）就**拿不到退出码**，所以"执行成功"只能做到"确实提交并执行了这一行"，
  做不到"退出码为 0"。真要做需要给本地 shell 装 prompt 钩子，SSH 远端装不了。
- `read -p "Name: "` 这类**回显但非命令行**的输入会被记成一条命令；密码提示不回显，反而因为读不到
  文本而自动不记录。

## 第十二批：文件传输的独立进度窗口

用户原话："文件上传下载 单独有个窗口何以查看进度"。

**做之前的样子**：`downloadFile` / `uploadFile` 就是 `read.pipe(write)` 然后等结束，**没有任何进度**，也没有
任何全局清单；SFTP 面板只能报它当前看着的那个会话，离开面板就看不见了。

### 决定（别轻易改）

- **传输清单位于主进程**（`src/main/transfers.ts`），不在渲染进程。窗口可以**在传输中途打开**，那时它必须
  显示真实状态，而不是"渲染进程恰好看到过的那部分"。窗口打开时先 `listTransfers()` 再订阅 `transfer:changed`，
  少了第一次拉取就会对着一个正在传的文件显示空列表。
- **进度节流 200ms，但合并而不是丢弃**：节流窗口内到达的字节必须跟着下一次广播一起出去，否则进度会停在
  最后一次被允许广播时的百分比。
- **取消是一种结局，不是错误**：取消就是销毁两个流，而销毁后的流看起来和正常结束一模一样，所以
  `finishTransfer` 遇到 `cancelled` 不改写状态，并且 `endTransfer` 给调用方返回 `{ok:false, cancelled:true}` ——
  否则面板会弹"上传成功"，而文件只有一半。
- **`sftp.ts` 里等的是"哪个先到"**（`settled()`：end / close / error），不是只等 `end`：被销毁的流永远不发
  `end`，只等它会让 Promise 永远挂着，窗口上就留下一个永远不会结束的任务。
- **速度/ETA 在窗口里算**（两次读数差分 + 平滑），不由主进程发：它们是"观察"的属性，窗口关着的时候发它们
  没有意义，而且发过去的值窗口还得再推导一次才对得上。
- **原生文件对话框只是前端**：传输本身走 `transfer:upload` / `transfer:download`（路径已知），
  `sftp:upload` / `sftp:download` 只是先弹对话框再调它们。这样探针能真跑传输 —— 也顺便给将来的拖放留了口子。
- 快捷键 `Ctrl+Shift+J`（`openTransfers`，builtin，可在设置里改）。

## 第十五批：SFTP 下载极慢 + 拖拽上传

用户原话：①"sftp 下载为什么这么慢 超级慢，别的工具对比 同环境 10M/s 这边半天都不动 几乎为0"；
②"新增 文件拖拽至 sftp 位置 实现文件上传"。

### 根因与结论（重要，别再走回头路）

- **旧实现是"一次一个读请求"**：`sftp.createReadStream()`（`fastGet` 同理）等一个块回来才发下一个，
  于是速度 = 块 ÷ 往返。32 KB / 70 ms ≈ 0.5 MB/s；远端往返 200–300 ms 就只剩 0.13 MB/s —— 正是用户
  说的"几乎为0"。**改法就是把固定数量的块保持在途**（`pump()`，128 KB × 16 = 2 MB）。
- **实测数据（务必保留这段，免得下次又白测）**：主机 82.156.226.192，16 MB —— 上传 2.2 MB/s、
  下载 0.46 MB/s；顺序 32K/64K/256K/1M 与 `fastGet` 并发 64 **全部 0.46 MB/s**（34.88–34.92 s，
  时间几乎一模一样 ⇒ 不是往返受限，是**这条线路被限速**）；系统自带 `scp` 拉同一个文件
  **34.85 s / 0.46 MB/s**。
  ⇒ **本机这条线路无法用来验证速度改进**，任何"提速"断言在这里都是假的。
- 因此并发性改用**替身 SFTP**（每次请求延迟 20 ms）直接验证：32 块顺序需 ≥640 ms，实测 155 ms（下载）
  / 127 ms（上传）。这条断言与网络无关，且在旧实现上必然失败 —— 这才是可迁移的证据。
- **取消**：`fastGet` 的 `step` 返回值在 ssh2 1.17 里被忽略（读不了源码别信文档），所以是自己写的
  `pump()` 循环才让中止生效：`aborted()` 在每个块之间检查，实测 32 块读到 16 块即停。
- 块必须**按自身偏移写**（`out.write(buffer, 0, bytes, position)`）：并发完成顺序不定，追加写会把文件写乱。

### 拖拽上传

- Electron 32+ 的 `File` 上**没有 path**，要用 `webUtils.getPathForFile`（主进程 preload 暴露
  `pathForFile`）。
- 但只认 `files` 不够：从很多文件管理器拖过来只有文本。所以还读 `text/uri-list` / `text/plain`，
  去掉 `file://`、解码、并处理 `file:///C:/...` 前导斜杠；不是绝对路径的一律丢弃，不猜。
- 多个文件按顺序传：一个 SFTP 通道上并行十几个上传只是在互相排队。
- 探针用 `DragEvent` + `DataTransfer`（`text/uri-list`）驱动，能覆盖整条链路。

## 第二十八批：REST 请求头读得懂单引号 + 两个页签带着数据切换

用户原话："restful 接口工具 请求头那里 单引号 被识别不是 json 处理一下；以及 逐条 或者 json 页签
切换的时候 带着数据 切换 现在是切换之后之前写的就没有了"。

### 两个 bug 是同一条链

- 从控制台 / Python 复制出来的对象字面量是**单引号**的（`{'Content-Type': 'application/json'}`），
  它不是 JSON。原来的 `parseHeadersJson` 只在 `JSON.parse` 失败后**看到 `{`/`[` 就直接判 not-json**，
  于是这种粘贴必判错 —— 这是第一个 bug。
- 而 JSON 框的文本**只在解析成功时才写进 `request.headers`**，点 JSON 页签又**无条件用
  `request.headers` 重写那个框**。于是没解析成功的文本（唯一的一份）一进一出就被覆盖 ——
  这就是"切换之后之前写的就没有了"。两个 bug 叠在一起：单引号 → 判错 → 切页签 → 文本没了。

### 改法

- 纯逻辑抽到 **`src/shared/restHeaders.ts`**（`parseHeadersJson` / `requoteSingleQuoted` /
  `headersJsonOf` / `HeaderJsonProblem`），页面只负责调用。
- **单引号只翻译引号，不放松判断**：`requoteSingleQuoted()` 把对象字面量的单引号翻成 JSON 的
  双引号（双引号区段逐字节复制，所以 `{"note": "it's fine"}` 里的撇号不会开字符串；单引号区段里
  `\'` 去转义、`"` 加转义），翻译后的文本**仍然要过真正的 `JSON.parse`** —— `{ 'X-Broken': }`
  照样报 not-json，不会变成一条名叫 `{ 'X-Broken'` 的头。
- **页签切换靠"行数据签名"**：`headersJsonForRef` 记住"JSON 框上次与行一致时 `request.headers`
  长什么样"（用 `headersJsonOf` 算）。切到 JSON 时只有签名变了（选了模板、改了行）才回填；
  否则**原样保留用户正在敲的文本**（还会留着那条解析错误提示）。JSON 解析成功时把签名刷新，

## 第三十批：闸门提速与分级（verify:fast）

用户原话："优化一下跑闸门……优化一下 case 提升一下效率，以及以后修复不相关的代码可以不用跑
不相关的 case，评估好风险。每次回归太慢了"。

### 慢的根子

`verify` 是 53 步 `&&` 链，其中 **49 个套件每个都先 `npm run build`**——每次 6–8 秒，
光重复构建就是 **5–6 分钟纯等待**；再叠加每个套件的 npm 包装开销、逐行 PASS 刷屏、
探针窗口没有注册 `app:isFullScreen` handler 产生的几十行 stderr 噪音。

### 改法：`npm run verify:fast`（`scripts/verifyfast.cjs`）

- **构建一次**，然后逐套件直接执行它自己的命令（从 package.json 的 `verify` 脚本解析顺序，
  套件命令剥掉 `npm run build && ` 前缀——**顺序与成员以 verify 脚本为唯一事实来源**，
  verify 改了它自动跟着变）。
- **输出纪律**（用户拍板）：控制台每个套件只打两行（`→ 名字 (n/总数)` + `✓ 98/98 · 28.2s`）；
  完整详细输出写 `node_modules/.verify/<套件>.log`（gitignore，绝不进 release 产物）；
  只有失败才把 `FAIL` 行 + 末尾 8 行打上屏；`app:isFullScreen` 噪音在**上屏层**过滤
  （日志文件里保留全量）。`build` 也算一步，失败就停。
- **定向跑**：`--only rest,s3`（名字可省 `smoke:` 前缀；写错的套件名直接报错并列出全部可选，
  防手滑跑了个寂寞）。四项检查照跑（`--no-checks` 可省）。另有 `--skip-build` / `--timeout N`
  （默认 15 分钟，超时杀整个进程树）。
- **串行标注是证据式的，不是手维护清单**：套件源码里出现测试链路 `82.156.226.192`、
  或命令没有独立 `--user-data-dir`、或命中负载敏感名单（memory/gesture/geom，交接页口径），
  就标串行。当前 49 个里 **20 个串行**（deps/ssh 无数据目录，ui/features/ui2-5/regress/
  duplicate/reconnect/tunnel/drawer/share/layout 真连链路，geom/memory/gesture 负载敏感）。
  `--list` 能打印整张计划表和每个串行的原因。
- **并行默认关（jobs=1）**：因为大半套件真连同一台测试机，并发上去可能触发 sshd 限流造成
  假 FAIL。`--jobs N` 是**选择加入**：串行套件独占整个跑批器（按顺序做屏障），
  其余填满 worker；偶发红先单独重跑再定性。

### 分级底线（用户拍板，已写进铁律）

1. **日常**：改了什么跑什么——`npm run verify:fast -- --only <相关套件>`，四项检查照跑；
2. **推 origin 前**：`npm run verify:fast` 全量；
3. **发版/打标签前**：原版 `npm run verify`（老规矩：清 smoke-data，EXITCODE=0 且 0 条 FAIL）。

**不许定向的情况**：动了 `src/shared/`、`src/main/store`、preload、ipc、`App.tsx`、
i18n 机制——这些被所有套件依赖，定向跑会漏。

### 实测

- 定向：`--only rest`（含四项检查）**55 秒**（build 一次 14.3s + rest 28.2s）。
- 全量 verify:fast 串行（jobs=1）：**EXITCODE=0，53 步 · 19m49s**。老闸门同样的套件时间还要叠
  49 次构建（≈5.7 分钟）与 npm 包装（≈1.5 分钟），即约 27 分钟。
- 全量 verify:fast **jobs=4**（用户要求试跑的一轮）：**EXITCODE=0，53 步全绿 · 15m12s**，
  **零偶发红**——并发调度过了真全量的考验。比老闸门快约 44%。
- 最慢五步（将来优化 case 先看它们）：wellbeing 3m03s、features3 1m25s、scale 45.8s、
  hosts 44.8s、repeat 39.7s。再往下压的余地：串行 20 步 ≈7.8 分钟是硬地板；
  调度器保持文档顺序、串行步当屏障，所以 wellbeing（3 分钟）会拖住并行道的尾巴——
  想再快得先拆 case，不是调 jobs 数。

## 第三十一批：`~/.ssh/config` 导入（发版 v2.4.0）

### 结构（三层，各管各的）

- **`src/shared/sshConfig.ts` —— 纯解析器**，不碰文件系统。语义照 OpenSSH 的
  「先到先得」：`Host` 行的每个参数是 pattern-list（可逗号分隔），`*`/`?` 通配、`!` 排除；
  块按文件顺序走（`Include` 在原地拼进 token 流），每个选项**第一个命中的值生效**——
  这正是 `Host *` 尾块该有的行为（补默认、不覆盖已设的）。字面量 pattern 才是可导入主机，
  纯模式块（`Host *`、`Host web-*`）只出默认值。**刻意不做的**：`Match` 块整个跳过
  （离线判断不了运行时条件，乱猜不如不猜）；`Include` 不展开 glob；只取第一个
  `IdentityFile`（TermDeck 会话只有一个私钥路径）。`~`/`%d` 展开用**注入的 home**，
  解析器不读 `process.env`（共享层铁律）。
- **`src/main/ssh/SshConfigFile.ts` —— 读文件的薄层**。路径可用 `TERMDECK_SSH_CONFIG`
  覆盖（同 `TERMDECK_KNOWN_HOSTS` 的理由：探针不碰开发者真实配置）。**展开后的私钥路径
  在这层 `normalize`**：Windows home 是反斜杠、config 里是正斜杠，混着写探针没法断言、
  会话编辑器里也不好看——这是探针抓出来的真实问题，不是探针的错。
- **IPC `sshconfig:peek` / `sshconfig:import`**。peek 返回解析结果加 `duplicate` 标记，
  判重规则与 share 导入同一条 `sessionKey`（用户名+主机+端口）；import **自己再滤一遍重复**
  （防 peek 之后树变了），`addSessions` 一次写盘一次 commit。凭据层不碰：`IdentityFile`
  → key 认证，没有私钥的按密码认证导入（连接时问密码，与手工新建一样）；
  `ProxyJump`/`ProxyCommand` 抄进备注并写明「未生效」——不静默丢，也不假装能跳板。

### 高亮：硬件地址整段框住

- **根因**：`mac` 规则写的是**正好六组**（`(?:[0-9a-f]{2}[:-]){5}[0-9a-f]{2}`），而正则末尾的
  单词边界在第六组后面那个冒号处就成立 —— 于是一条 20/21 组的长地址只框住前 6 组（17 格），
  后面全是白的。截图那条是 **21 组、62 字符**，正是这个形状（`brd` 那条同理）。
- **修法**：`{5}` → `{5,}`，六组及以上整段一次框住；普通六组 MAC 行为不变。InfiniBand 端口
  地址与 EUI-64（八组）都进来了。
- 规则标签跟着改：`MAC addresses` → `MAC / hardware addresses`（词表 `highlight.rule.mac`
  改成 `MAC / 硬件地址`）—— 它现在画的不只是 MAC。
- **证据**：旧代码上 62 字符地址只框 17 格（`smoke/highlight.cjs` 新增 3 条，现 30/30）。

### 点标签后的键盘 + Backspace 关会话（同一个根因）

- **根因**：dockview 在 **pointerdown** 激活面板 → 我们的 `onDidActivePanelChange` 同步把
  焦点交给终端 → 紧接着**浏览器 mousedown 的默认动作**又把焦点交给**标签元素本身**
  （`div[tabindex="-1"]` 是可以点着聚焦的）。于是：
  ① 窗格看着是活动的，打字却进不去，要再点一下；
  ② Backspace/Delete 落在标签上，被 dockview 的 tablist 键位当成「关闭这个面板」
  （dockview-core 里就是 `case "Delete" / "Backspace" → _closeTab`）—— 终端里 Backspace
  是最常用的键，误关会话不可恢复，这是用户明确要求取消的。
- **修法**（都在 App.tsx 的 dock 引导 effect 里，全部带清理）：
  - `mousedown`（捕获，dock 容器）记下被按的标签 panel id → `mouseup`（捕获，**window**，
    因为拖拽可能在容器外松手）在**默认动作之后**把键盘交给那个 pane 的终端（`setTimeout(0)`）；
    `focusPolicy` 仍是最后一道闸，输入框/模态不会被抢；
  - `keydown`（捕获，dock 容器）拦掉**标签上的** Backspace/Delete：`preventDefault +
    stopPropagation`（赶在 tablist 看到之前），并把键盘交回该窗格的终端。
- **证据**：旧代码 19/22、退出码 1（焦点停在 `DIV.dv-tab`、按键只产生 xterm 的 focus-out
  序列、Backspace 把面板从 2 关到 1）；修后 `smoke/keys.cjs` **24/24**（含两条直接打在
  「标签持着键盘」状态上的断言：Backspace 不关面板、键盘交回终端）。

### 探针：为什么以前没抓到（记入陷阱）

- 原来的焦点断言用 `dock.getPanel(id).api.setActive()` —— 那是**键盘/API** 那条路，一直是绿的；
  用户走的是**真鼠标**那条路。现在这条断言改用 CDP `Input.dispatchMouseEvent` 打在标签的
  真实坐标上。
- 但 CDP 注入的鼠标事件**不执行浏览器「按下即聚焦」的默认动作**（实测：只按，焦点不动）。
  所以探针在 `mousePressed` 之后手动 `tab.focus()`，把真实顺序（按下 → 标签拿到焦点 → 松开）
  还原出来 —— 否则探针会假绿。**这是本批最有价值的一条教训**。
- 另一条：`check:probes` 会抓探针里的 `\b`（模板字符串里会被当退格转义），注释里写正则
  元字符也不行 —— 用「单词边界」这样的汉字描述，别写 `\b`。
