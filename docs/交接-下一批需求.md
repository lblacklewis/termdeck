## bug 9 的三处改动（一个 bug 三处才修得动）

1. **主进程在会话退出后保留蓝图**（`session:exit` 不再 `blueprints.delete`）。蓝图是这个窗格
   "怎么连上去的"唯一记录：主机、凭据、私钥、端口。没有它，一个 quick connect 断掉之后
   Reconnect 无从下手。释放点在 `session:close`（窗格关掉时），所以不会累积 —— 在屏的窗格
   就是持有它的那一个。
2. **`session:reconnect`**：与 `session:duplicate` 共用 `createFromBlueprint()`，区别只在错误
   文案和调用者。副作用是"复制一个已经结束的窗格"现在也能用（以前会报 NOT_DUPLICABLE）。
3. **渲染层**：`bindSessionToPanel()` 把"把某个窗格指向一个新会话"的记账抽成一处（原来内联在
   `addSession` 的 `if (existing)` 分支里），`reconnectEndedRef` 复用它；`TerminalPanel` 里
   `ended` 是局部状态，所以**必须在 `session` 变化时清掉**，否则重连成功后遮罩还盖在上面。

## 每项的关键决定（别轻易改）

- **内存纪律是"用到才申请"**，不是"少占内存"：工具页各自一个 chunk、按需 import、离开即卸载；
  主进程的 store/manager 全是 `??=` 的懒单例；隧道从不自动启动（启动时只恢复定义）。
  `smoke:memory` 是这条纪律的闸门：查构建产物（工具页代码不在启动 bundle 里）+ 运行时
  （打开/离开的增量和收敛）。
- **测量内存必须先强制 GC**（探针里 `--expose-gc` + 每次测量前 `window.gc()`）。不加的话每轮
  稳定 +3 MB，看着像泄漏，其实只是 V8 没回收；加了之后是 +3.0/+0.0/+0.1/+0.3。
  **"没回收"和"被留住了"是两个结论，只有后者是 bug。**
- **SFTP 默认折叠**靠的是结构而不是开关：`SectionFrame` 在 `collapsed` 时不渲染 body，
  面板根本不挂载，effect 不会跑，也就没有第二条连接。迁移老用户用的规则是"存储里没有
  `collapsed` 字段 ⇒ 跟随内置默认"——用户亲手展开过会写下 `collapsed: false`，不会被覆盖。
- **tag 筛选是 AND（多选）**：`tagFilters` 是数组，主机要同时带全部所选 tag。搜索框也搜 tag
  （tag 是大家记住一台机器的方式之一）。断言写法是"剩下的每一行都满足条件"，不是固定行数。
- **快速脚本与打字同一条规则**：只发给**在屏**的窗格。隐藏的标签页有活的 backend，但用户看不见
  它 —— 往里写命令是那个"某些窗格没收到输入"的观感的来源。
  `sendToAll()` 与 `routeInput()` 的两个刻意不同：**包含**当前窗格；收整行不收按键；多行逐行提交
  （一整块粘进 readline 会被当成一条长命令）。
- **断线重连不劫持活着的窗格**：`deadPaneFor()` 只认 `endedSessionsRef`。改这里之前先看
  `smoke/reconnect`。
- **telnet 是自己实现的字节状态机**，串口用可选依赖 `serialport`（缺了要明确报"不可用"）。
- **隧道永不自动重连**；改目标的隧道必须停掉（`sameTarget()`，改名不算改指）。
- **REST 与 S3 都走主进程**：渲染层是 `file://`，页面里 `fetch` 受 CORS 限制。渲染层自己从不碰网络。
- **S3 secret key 只留内存、不落盘**（`rememberSecret` 为真才存）；SigV4 手写，不引 AWS SDK。
- **`sanitiseTree()` 是读路径白名单**：`SavedSession` 上新加字段必须同时加进去，否则存了也会在
  重启后消失。这个坑踩过一次。

## 踩过的坑（这批新增的）

1. **`performance.getEntriesByType('resource')` 在 `file://` 下是空的**：用它查"某个 chunk 有没有
   被加载"会因为看不见而**通过**。改成查构建产物（页面 test-id 不能出现在 `index-*.js` 里）。
2. **探针自己也会被测进去**：从主进程每 150 ms 轮询一次页面是否出现，那些 `executeJavaScript`
   本身就在渲染层堆里占量。改成一次调用、等待放在页面内完成。
3. **`webContents.getProcessMemoryInfo` 在这个 Electron 版本不存在**，用 `app.getAppMetrics()`
   （字段是 KB）。
4. **PowerShell 的 here-string 拼接把脚本内容写进了源码文件**（`ipc.ts` 被塞进 `Rep "..."` 那几行）。
   教训：**改源码一律用 `edit` 工具**，PowerShell 只做只读查询和 git 操作。
5. **探针里不能有反引号和 `\d`、`\/` 这类反斜杠**（会被模板字符串吃掉）。`npm run check:probes`
   会拦（49 个文件逐个解析），改完探针立刻跑它。
6. **断言的正确性要查证**：`features3` 里"每个窗格都收到"曾失败，实际是那两个窗格堆叠、只有
   一个在屏 —— 后来发现同一套件后面印着 `visible=2 hidden=1`。**先确认断言对不对，再改代码。**
7. 时序断言用条件等待（`waitFor(条件)`），不要写死 `wait(2000)`：`smoke:reconnect` 曾因此
   偶发失败一次。
8. **打包机没有 Python**：electron-builder 默认要重建原生依赖（`@serialport/bindings-cpp`），
   node-gyp 报 "Could not find any Python installation to use"。这两个依赖是**可选依赖**且都自带
   NAPI 预编译（没有 ABI 后缀就是 NAPI，Node 与 Electron 通用），所以 `build.npmRebuild = false`。
   别只凭推理关掉它：先在 Electron 里真的 require 一次并用起来，再启动**打包后的 exe** 用 CDP 确认
   应用内部能开出本地 shell（node-pty 走 IPC）—— 两步都过了再留这个开关。
9. 探针断言**不要写恒真表达式**（`x || true`），也别写"只验证消失"的断言 —— 先决条件从未成立时它会
   静静通过（`smoke:reconnect` 就有一条是这样混过去的）。

## 第三批：断线重连保 history（`8768603`）

三个需求共用一层机制，所以一起做：

1. **重连后历史不丢、还在同一个窗格**
2. **Ctrl+R 重连**
3. **被动断开自动重试，次数与间隔可设置**（默认 3 次 / 10 秒）

| 项 | 兜底 |
| --- | --- |
| 同 id 重生、历史保留、Ctrl+R 两个方向 | `smoke:reconnect` 30/30 |
| 自动重试（挂断后自愈 / 拒连后放弃） | `smoke:transport` 19/19 |

### 决定（别轻易改）

- **重连是"重生"不是"新建"**：`SessionManager.create(..., reuseId)` 沿用原 session id。终端是按
  session id 建的，id 不变终端就不重建，滚动缓冲自然留着。改回新建 id 等于把 history 丢掉。
- **退出后不删会话记录**，只把 backend 置空。记录里的滚动缓冲（≤256KB/窗格）就是历史，窗格挂载时
  还能 replay。`list()` 只返回活的，所以"有几个会话"的语义没变；记录在窗格关闭时释放。
- **`attach()` 里的 backend 同一性判断**：被替换掉的旧 backend 迟到上报 exit 时不许影响新连接。
  没有这一条，重连成功后紧接着就会被上一条连接的退出事件打死。
- **"被动"= 不是应用要关的 + 退出码不是 0**。网络掉了、对端消失 → 退出码空 → 重试；用户敲 `exit`
  （退出码 0）、关窗格、Ctrl+D → 不重试。
- **一次掉线事件内累计次数**，连接稳定 10 秒才清零。否则"开起来就断"的传输（telnet/串口报成功只代表
  socket 开了）会无限重试，"3 次"就形同虚设。
- **重连"成功"要验活**：`reconnectSession` 返回 ok 之后还要确认会话仍在，否则会绑定一个已经死掉的
  会话，把遮罩清掉、留下没有任何说明的死终端。
- **Ctrl+R 只在已结束的窗格上生效**，活着时放行给 shell（readline 的反向搜索）。与 Ctrl+D 同一条规矩。

### 顺带修的真 bug

telnet 后端 socket 掉线时上报 `exit(0)`（假装对端正常退出），使"掉线"与"用户登出"从外部无法区分 ——
自动重试正好依赖这个区分。telnet 没有退出码，现在如实报 `null`。

## 第四批：抽屉会话区搜索（`861539c`）

需求：终端页抽屉的会话区也能搜，按 tag + name + ip。

| 项 | 兜底 |
| --- | --- |
| 名称 / 地址 / 标签搜索、无匹配提示、清除与 Esc | `smoke:drawer` 80/80 |

### 决定（别轻易改）

- **搜索在树里，不在 App 里做过滤**：`SessionTree` 收 `query` + `onQuery`，`matchesFilter()` 同时
  看标签芯片和输入框。名字、地址、标签是同一件事的三种记法，分开做会漂。
- **搜索时收起空文件夹**，没搜索时全部保留（空文件夹也是拖放目标）。这条区别是有意的：搜索要的是
  "匹配的那几台"，不是整棵树的形状。
- **`query` 放在 App 而不是 `SessionTree` 内部**：抽屉分区可以折叠、可以重排，组件一卸载查询就没了。
- 探针夹具里因此多了一台 `web-1`（`10.9.8.7` / tag `staging`）：只有一台主机时，"搜到了"和"没搜"
  看起来完全一样。

## 第五批：全屏程序里不提示（`7abb30b`）

需求：vim、less 以及其它场景不要输入提示，仅在命令行处支持。

| 项 | 兜底 |
| --- | --- |
| 全屏时不弹补全、原本打开的收起、退出后恢复 | `smoke:suggest` 24/24 |

### 决定（别轻易改）

- **只认备用屏幕这一个信号**：`term.buffer.active.type === 'alternate'`。vim/less/man/htop/tmux
  进出全屏都切它，这是"它接管了屏幕"的起止时间，不需要猜提示符长什么样。
- **两处都要拦**：`feed()`（连按键镜像都不记）和 `sync()`（由 `term.onWriteParsed` 驱动，把已经
  打开的窗口收起）。只拦 `feed()` 会漏掉"补全开着的时候启动了 vim"——那之后没有按键可等。
- **顺带修掉的真 bug**：以前在 vim 里按回车，屏幕上那一行会被 `report()` 当成"刚运行过的命令"写进
  历史。`feed()` 早退之后自然就没了。
- **已知边界**：`sudo` 密码提示、`[y/N]` 确认这类**不切屏**的场合拿不到可靠信号；`less -X` 也识别
  不到。要更准得读 shell 自己的提示符，那是另一件事（写进发行说明的"已知边界"了）。

## 第六批：快捷指令的快捷键与焦点（`a216005`）

需求三条：① 点完快捷指令光标要回到窗格；② 快捷指令支持自定义全局快捷键；③ 快捷键冲突要提示并拦截。

| 项 | 兜底 |
| --- | --- |
| 焦点回到终端、快捷键能执行、冲突报出并拦住保存 | `smoke:snippet` 22/22 |
| 抽屉底部图标仍是横排（同批修掉的样式回归） | `smoke:drawer` 82/82 |

### 决定（别轻易改）

- **快捷键存在 `Snippet.keys` 上，不进 `settings.keybindings`**：改名跟着走、删除一起消失。塞进键位
  表的话，删掉快捷指令会留一条指向空气的绑定 —— 按下去什么都不发生，而且冲突检查也查不到它。
- **派发用 `snippet:<id>` 作 handler id**，`allBindings = keybindings + 带键的快捷指令` 交给
  `useShortcuts`。所以"终端里也能按""单键不抢""返回 false 放行"全部复用现成规则，没有第二套逻辑。
- **冲突表是同一个命名空间**：两个快捷指令撞键、或快捷指令撞内置，走同一条判断与同一个保存拦截。
  `sanitiseSnippets` 逐字段重建，新字段必须写进去，否则**读盘即丢**（这个坑已经踩过）。
- **冲突提示要能指向"改哪里"**：列出双方名字 + 把那一格标红 + 保存时给中文说明。只报"有冲突"等于
  让用户自己去列表里找。
- **焦点回到的是会话，不是面板**：恢复出来的窗格面板 id 是旧会话 id，写和聚焦都得先经 `liveIdFor`。

### 已知未做（用户没要求，别自作主张）

- **同屏广播的快捷脚本那一条，发送后焦点仍留在输入框**：它是一个表单（可能连发几行），把焦点抢到
  终端反而碍事。如果用户希望统一成"发完就回窗格"，改 `App.tsx` 里 `onSendScript` 一处即可。
