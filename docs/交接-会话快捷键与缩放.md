## 计划外多修的两个真问题

写探针时被断言抓出来的，都修在应用里：

1. **切窗格会把键盘丢给 `body`。** dockview 隐藏旧窗格，被隐藏的元素留不住焦点，
   于是 `Alt`+数字切过去之后你打的下一个字谁都收不到。新增 `activatePanel()`：
   **只有**按键前焦点就在终端里时才把新窗格聚焦（在设置输入框里按 `Alt+[` 不会把光标
   抢走）；`Ctrl+Tab` 走同一条路。
2. **xterm 把 `Alt`+数字 / `Alt+[` / `Alt+]` 吃掉了。** xterm 先于 window 拿到按键，
   对它处理的键会调 `stopPropagation`，所以窗口上的监听器根本收不到 —— 快捷键恰好在
   「你真正要按它的地方（终端里）」完全无效；而且它把这些键当成「Alt+字符」，会往 shell
   发 `ESC 2` / `ESC [` / `ESC ]`，其中 `ESC ]` 打开一个 OSC 字符串，之后敲的字符全被
   行编辑器吞掉。修法：`term.attachCustomKeyEventHandler` 把这一族让出去。

## 本轮学到的规矩（写进探针卫生）

- **注入模板里不能出现反引号**（注释里引用选择器也不行）：会提前结束模板。而
  `node --check` 可能仍然通过（剩下的注入代码当成普通语句就合法了），只在运行时炸成
  `x is not defined`。`scripts/checkprobes.cjs` 现在会检查「反引号必须成对」。
  **第29轮又踩了两次**，两次都只是写注释时顺手引用了 `keyCode` / 元素名。
- **探针要派发到指针底下的那个元素**，不要直接派发到目标元素：否则「坐标不对但事件送达」
  会让一个根本不可能成功的交互看起来通过（`smoke:drawer` 的停靠检查就是这样骗过了我）。
- **按键要带上真实 `keyCode`**：xterm 按 `keyCode` 分派，只给 `key` 的合成
  `KeyboardEvent` 会被它当成 keyCode 0 忽略，事件于是照常冒泡到 window、探针报绿，
  而真实按键走的是另一条路（`stopPropagation` + 往 shell 发 ESC 序列）。派发对象也应当是
  `document.activeElement`，并顺手断言「焦点确实在终端里」。
