# TermDeck v1.13.1

## 修复：配色方案与高亮规则不再藏在开关后面

上一版（v1.12.0）把输出高亮做成了「开关 + 配色方案 + 8 条规则」，但**配色方案和规则只在开关
打开后才渲染**。默认是关的，所以打开 设置 → 终端 只看到一个勾选框，看起来**像这个功能根本没做**：

> 「配色方案没做吧？就是高亮显示的那个」

现在这三样**一直可见**：开关关闭时，配色方案下拉与规则色块**置灰不可点**，而不是消失。
状态依然一眼可辨，功能也不会再被误认为不存在。

配色方案一共 **4 套**（都在，没变）：

| 方案 | 风格 |
| --- | --- |
| 经典 | 亮色前景，oh-my-zsh 那一挂，适合深色主题 |
| XShell 色块 | 前景+背景成块，深浅主题都清楚 |
| 柔和 | 中等色调，适合浅色主题 |
| 单色 | 信息类同一个颜色 |

规则 8 条（IP / 链接 / 邮箱 / MAC / 文件路径 / 错误 / 警告 / 成功关键字），每条带一个显示**真实配色**
的 `Aa` 色块，可逐条开关；默认开 7 条，文件路径默认关。

## 验证

`smoke:highlight` **16 → 18 条**，新增两条正对着这次的问题：

- **开关还没打开时，配色方案就是可见的** —— 断言 `picker` 存在、`schemes === 4`、`rules === 8`；
- **关闭状态下它们是"不可用"而不是"不存在"** —— `picker.disabled === true` 且规则复选框 `disabled`。

旧实现上这两条必然失败：那段 JSX 当时是 `{settings.highlightEnabled && (…)}`，条件为假时元素
根本不在 DOM 里（`picker=false schemes=0 rules=0`）。

其余 16 条（匹配几何、逐字符配色、方案切换、规则开关、复制仍是纯文本）全部照旧通过。

完整闸门：**EXITCODE=0**、**46 套件**、0 条 FAIL；`check:i18n` 620 源码键 / 589 目录键、0 stale；
**54 个探针**。
