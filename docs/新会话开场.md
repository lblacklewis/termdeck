## 说明

- **为什么强调先读交接文档**：交接文档按批次累积了二十六批的决定与坑（比如"面板参数必须 `updateParameters`"、
  "探针模板里不能有反引号"、"工具页的整页中文不是补词表就完了"、"`LayoutState` 加字段必须同时改 sanitise"、
  "筛选必须压过折叠"、"批量操作必须一次 IPC 一次 commit"、"重连不许抢焦点"、
  "高亮只能用颜色、绝不能注入转义序列"、"默认关闭的功能它的选项要一直可见一直可改"），新会话不知道这些就会重犯。
- **为什么要先看 git 状态**：上一轮可能还有未提交的改动，或者版本号已经变了，别在错误的前提上开工。
- **为什么把"待办候选"和"这次要做的是"分开**：候选只是备忘；不写清楚这次做什么，容易被理解成"全都要做"。
- **为什么 macOS 这批要拆成 A/B**：这台开发机是 Windows，**mac 产物打不出来、也跑不了**。
  把"能在 Windows 上判对错的代码与探针"和"必须真机验收的部分"分开写，才不会出现"声称验过了其实没跑过"。
