## 说明

- **为什么强调先读交接文档**：交接文档按批次累积了 17 批的决定与坑（比如"面板参数必须 `updateParameters`"、
  "探针模板里不能有反引号"），新会话不知道这些就会重犯。
- **为什么要先看 git 状态**：上一轮可能还有未提交的改动，或者版本号已经变了，别在错误的前提上开工。
- **为什么把"待办候选"和"这次要做的是"分开**：候选只是备忘；不写清楚这次做什么，容易被理解成"全都要做"。
