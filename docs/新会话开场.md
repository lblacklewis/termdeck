## 说明

- **为什么强调先读交接文档**：交接文档按批次累积了二十八批的决定与坑（比如"面板参数必须 `updateParameters`"、
  "探针里不能有反引号"、"工具页的整页中文不是补词表就完了"、"`LayoutState` 加字段必须同时改 sanitise"、
  "筛选必须压过折叠"、"批量操作必须一次 IPC 一次 commit"、"重连不许抢焦点"、
  "高亮只能用颜色、绝不能注入转义序列"、"默认关闭的功能它的选项要一直可见一直可改"、
  "切窗格要把键盘交给新窗格（终端的 helper textarea 本身也是 textarea，判定顺序不能换）"、
  "REST 请求头有两个编辑器一份数据（别每次从行重写，没解析成功的文本是唯一一份）"、
  "请求体高度存的是拖拽不是布局（只认内联 style.height）"、
  "**worktree 里打包不要 junction node_modules**：electron-builder 会静默丢掉整个依赖树，产物能装能跑但窗口永远不开"、
  "mac 的应用菜单不能占 Cmd+W、退出项不能用 role:'quit'"），新会话不知道这些就会重犯。
- **为什么要先看 git 状态**：上一轮可能还有未提交的改动，或者版本号已经变了，别在错误的前提上开工。
- **为什么把"待办候选"和"这次要做的是"分开**：候选只是备忘；不写清楚这次做什么，容易被理解成"全都要做"。
- **为什么平台相关的活要先抽纯函数**：macOS 的验证机器不一定在手边（这批就是"代码先行、真机后补"）。
  把"选哪个 shell / 用哪套默认键位 / 菜单里有哪些 role"做成 `(platform, ...) => 结果` 的纯函数，
  探针注入 `'darwin'` 就能在 Windows 上断言；只有 PTY 真的起不起得来、`system_profiler` 真实输出的形状、
  Gatekeeper 与钥匙串的行为、串口设备枚举这几件必须真机，§9 里逐条写了命令。
