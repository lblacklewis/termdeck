# TermDeck v1.8.0

## 改进

**REST 页面整页中文**

中文界面的最后一块硬伤。工具栏、字段、按钮、报错一直都在，但这一页一个字都没翻 —— 源码里有 48 条
`restpage.*` 文案，词表里一条都没有，于是**整页都在走英文回退**。（`check:i18n` 抓不到这种缺失：缺翻译
只是个 note，不是失败，所以它整整活过了一个版本。）现在整页翻了：

- 字段：方法 / URL / 超时（秒）/ 请求头 / 请求体；
- 按钮与开关：发送、复制为 cURL、添加请求头、格式化 JSON、逐条 / JSON、接受自签名证书；
- 左右两列：历史、已保存的请求，以及它们的空状态（"发送过的调用会出现在这里。"）；
- 响应区：状态、响应头、显示全部行 / 折回前 400 行、搜索；
- 连 `aria-label` 与下拉里的 `<option>` 行也翻了 —— 那些不是"看得见的文字"，但读屏和键盘用户撞见的
  就是它们。

**内置模板的名字与说明也翻了**

7 个模板（Ollama、Elasticsearch、Prometheus、Health check…）的名字和那行说明来自**共享数据**
（`src/shared/restTemplates.ts`，探针也在断言同一份），所以译词按模板 id 取，**英文原文仍留在原处当回退**，
不在第二处复制英文。

**失败原因**

主进程自己决定的 4 句原因（不是一个 URL / 只支持 http(s) / 超时 / 重定向过多）现在带 `errorCode`，页面按
当前语言取词 —— 和这一页处理"请求头 JSON 写错"用的是同一套做法。英文句子照旧留在 `error` 里：它是回退，
也是日志和英文界面看的东西，所以**英文界面一个字都没变**。

Node 报的原始错误（`ECONNREFUSED`、证书、DNS）**故意没有翻**：那段文本本身就是有用的细节，没有可翻译的
句子，硬翻反而会让人搜不到资料。

**有意保留英文的几处**：`REST` / `URL` / `JSON` 三个词、示例值（`http://127.0.0.1:8080/health`、
`Content-Type`、`application/json`）与单位（`ms`、`B`、历史里的 `5s` / `3m` / `2h`）。这些不是句子，
翻成中文反而更难认 —— 与词表其余部分同一条政策（每一条都写在 `zh.ts` 的注释里）。

## 验证

完整闸门 `npm run verify`：41 套件全过、0 条 FAIL。`smoke:i18n` 9 → **20 条**，读的都是渲染后的 DOM：

- 逐项：工具栏、字段标签、两列标题、空状态、`aria-label`、下拉行、模板说明、主进程的失败原因；
- 一条**清单式**断言："这些英文一个都不许再出现"（`Send` / `Add header` / `Kept requests` / `Method` …）。
  这条才是能区分对错的东西：未翻译的版本必挂，而"页面里有中文"这种断言会被旁边的导航栏蒙过去；
- 失败原因那条等的是**这一次的新错误**，不是"屏幕上有错误"——上一步的错误还留在屏幕上，这是上一批踩过的坑。

证据：探针先写在**未改动的代码**上跑，20 条里 **9 条 FAIL**（唯一通过的是"选模板仍能填 URL"这条护栏，
它本来就该两边都过 —— 那是在防交互被我改坏）；改完 **20/20**。

另外，`check:i18n` 里识别"计算键前缀"的规则原来只认 `keybinding.` 这种**单层**前缀，现在允许前缀里带点，
于是 `restpage.err.*` 与 `restpage.tpl_name.*` 各自被**精确**豁免 —— 整个 `restpage.*` 并没有被放行，
`restpage.send` 之类写错照样报 stale。
