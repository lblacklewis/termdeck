## 🏗️ 架构

```
Electron 主进程（独占特权）
  ├── ssh2               SSH 通道（静态 import，避免 CJS namespace 问题）
  ├── @lydell/node-pty   本地 shell
  ├── CredentialStore    safeStorage → AES-256-GCM，密文落盘
  ├── LayoutStore        layout.json（dockview 布局 + 页面/栏位状态）
  └── fonts.ts           平台字体枚举
        ↕ 单一窄 preload 桥（contextIsolation，无 nodeIntegration）
渲染进程（React 19）
  ├── dockview 8.3       分屏/分组；v7+ 无 React 绑定，自写 ReactRenderer
  ├── @xterm/xterm 6     终端
  └── broadcast.ts       多窗格同时输入
```

## ✅ 验证方式

`npm run verify` = typecheck + 31 个探针套件，最后一个是 11 套主题 × 5 页面的 WCAG 对比度审计。

探针在真实 Electron 里驱动真实应用（真 PTY、真 SSH、真 DOM），不是只断言元素存在。

两条经验（都写进 README 的 Gotchas）：**探针必须点名自己那一个窗格**——所有终端 DOM 长得一样，`document.querySelector('.xterm-rows')` 拿到的是 DOM 里第一个窗格，结果就是旁边的窗格健康、被测窗格已经塌了却报绿；**探针必须重置它要断言的 store**——套件共用真实 `userData`，断言「刚好只有我刚建的东西」的用例在干净机器上过、第二次跑就挂。store 是**在第一次访问时构造并读文件**，所以「删文件」必须发生在任何 `storeAccess()` 之前；`smoke/clearstore.cjs` 的 `wipeProfile()` 直接删整个 userData 目录，所有套件都改成在 `registerIpc()` 之前调用它。

## ✅ 已解决：窗格偶发塌成 65px（根因：我自己加的「太小就跳过」守卫）

现象曾是：**同一个窗口内** `.td-dockview` 正常（1124x826），但 dockview 自己的 `.dv-dockview`/`.dv-grid-view` 停在 100x100，于是 pane 只有 65px、终端停在 80×24、时间戳列全空；**改窗口大小、重新加载页面都救不回来**，只有换进程才行。

根因不是 dockview：`dock.layout(w, h, true)` 不只是「读容器尺寸」，它会把停靠面**按传入的数字重设大小**。之前为了「别把占位尺寸传进去」加了 `if (width < 200 || height < 200) return` —— 而一旦停靠面塌了，容器读出来也是 100x100，这个守卫于是**跳过了唯一能纠正它的调用**，状态就永久化了。删掉守卫后每个 tick 都会重新按真实尺寸布局，自己就恢复了。

另外两处同类问题一起修掉：
- `dockSyncRef` 原本指向走 `requestAnimationFrame` 的 `syncLayout`；rAF 在不绘制时会被节流，延后的调用就是「永远不会跑」。改为直接指向同步的 `applyLayout`。
- 布局被纠正后，终端自己的 watchdog 可能早已停止，所以布局同步现在会顺带 `refitAll()` 让每个窗格重新测量。

验证：`smoke:chrome` 6/6、`smoke:geom` 5/5、`smoke:repeat` 8/8 全绿。

## ✅ 已解决：「复制连接」复制出来的是本地 shell

现象：右键标签页 →「Duplicate connection」，得到的是一个**本地 shell**（toast 直说「has no saved host」）。真因有两层：

1. **面板参数读不到。** dockview 的 `panel.api.getParameters()` 只有在调用过 `updateParameters()` 之后才有值；用 `addPanel({ params })` 建的窗格，参数交给的是渲染器，API 读回来是 `{}`。旧代码正是从 `params.session` / `params.savedSessionId` 里找主机，于是**永远**走兜底分支 → `createLocalSession`。表格里 `reloadPanel` 的「已保存会话」分支同理，一直是死代码。
2. **凭据只在主进程里。** 即使能读到参数，渲染进程也不知道那次连接用的密码（从加密库读的，或用户临时输入的），按标题/主机名反查已保存会话只是一种猜测。

所以复制改由主进程负责：`session:createSsh` 把「解析完的 `SshConnectOptions`」按会话 id 记下来，新增 `session:duplicate` 用同一份参数重开一条通道（本地 shell 也同理），**凭据不跨进程**，也不存在猜错主机/密码的可能。渲染进程只负责把新会话开成新标签页。

- 渲染进程的兜底改用**面板 id**（连接态的窗格 id 就是会话 id），占位符窗格会被主进程拒绝并给出「先重连再复制」，不再默默变成本地 shell。
- 「Reload / reconnect」走同一条 `session:duplicate`，SSH 窗格重新载入后还是 SSH。
- 重新载入会**保留窗格、换掉背后的会话**，两者 id 不再相同，因此新增 `liveSessionRef`（面板 id → 当前会话 id）：关闭/激活/侧栏列表都经它解析，否则关掉一个重载过的窗格只会关掉一个已经消失的旧会话，把活着的那条漏在后台。
- 双击标签页（`data-tab-panel-id`）与右键菜单同一个入口；终端里双击选词不会触发（只匹配标签条）。

验证：`smoke:duplicate`（19 项）——右键复制与双击复制都开第二条 **ssh** 会话，且往复制出来的窗格写 `uname -s` 能拿到远端回答；另有反向断言「终端里双击不复制」。

## ✅ 已解决：退出前二次确认

退出这个动作在这里比一般应用「贵」：每个窗格都是一条活着的 SSH 登录或本地 shell，关掉窗口就是一次性全部结束，而且没有撤销。所以窗口的 `close` 在**主进程**里被拦住（`src/main/quit.ts`），交给渲染进程弹一个应用内对话框，用户点 Quit 才真的退。

放在主进程而不是渲染进程，是因为窗口 X、Alt+F4、任务栏「关闭窗口」和 Electron 默认菜单的 Quit 全都只会到这同一个 `close`：拦一次就全覆盖，包括渲染进程根本不知道的那些路径。要点：

- 拦的是 `close` 的 `defaultPrevented` 路径，所以 `app.quit()` 发起的关闭同样会被取消并变成一次询问。
- 文案里写明**有几条活动连接会被关掉**——那些躲在别的标签页后面的连接正是最容易忘记的；数量取自主进程（它才知道每条后端是否还活着，重载过的窗格 id 和会话 id 并不相同）。
- Cancel 是默认按钮（`autoFocus`），Esc 也是取消，避免误按回车直接退出。
- 渲染进程已销毁时不再拦截，否则会留下一个关不掉的窗口。
- 快捷键用 **Ctrl+Shift+Q** 而不是 Ctrl+Q：Ctrl+Q 在终端里是 XON（恢复输出），吃掉它会破坏 shell 的流控。这个绑定按普通按键项加进 `DEFAULT_KEYBINDINGS`，因此设置页里可以直接改；`mergeKeybindings` 会把新内置项追加给老配置，不用迁移。

验证：`smoke:quit`（16 项）——X 会问、问的时候连接还活着、取消后连接没动、再点 X 还会问、Esc 取消、快捷键问同一个问题、点 Quit 才真的关窗且 `isQuitting()` 为真。这一套最后一步会真的退出应用，所以报告用 `fs.writeSync(1, …)` 逐条写，避免被进程退出截掉。

## ✅ 第23轮：抽屉分区 / 命令历史 / SFTP / 专注模式 / 休息提醒 / 锁屏

**抽屉分区可拖拽、可自定义显示。** `settings.sidebar.sections` 保存**顺序 + 可见性**（隐藏的分区保留位置，恢复时回到原处）。标题栏就是拖拽手柄，右键标题出菜单：隐藏本区 / 把某个隐藏的分区放回来；设置页 Wellbeing 里也有同样的勾选框。新增两个分区：

- **History**：主进程在 `session:write` 上把**真正敲下去的行**拼出来（方向键等 CSI 序列、退格、Ctrl+C/U、终端回包都排除，Enter 才算一条），落盘 `history.json`（上限 300 条，连续重复忽略），并广播 `history:changed`；点一条就是用当前窗格重跑它（补一个 `\r`）。
- **SFTP**：按**会话 id** 向主进程要目录，主进程用这条连接当初的 options 另开一个 SFTP 会话并复用（凭据不跨进程，host key 校验与终端同一条路径）。支持进入目录/返回上级/刷新/上传/下载（下载=另存为，上传=选择文件）。没连主机时给的是提示而不是报错。

**专注模式（F11）**：快捷键在主进程的 `before-input-event` 里处理——Electron 默认菜单本来就占了 F11，菜单快捷键在浏览器进程就被吃掉、页面根本收不到；`preventDefault()` 同时拦住菜单和页面，所以一次按键只会切换一次。绑定从设置里读，因此改键立即生效。开启后不渲染导航轨与快捷指令栏，**抽屉保留**（第24轮改的：专注模式是让窗格占满窗口，不是把切换会话的列表拿走）；`enter/leave-full-screen` 事件回传，用别的方式退出全屏时界面也会跟着还原。

**休息提醒**：只统计**窗口有焦点**的秒数，到点弹提醒。第24轮把里面那个 2D 小游戏删了——它比它要解决的问题更烦人；现在就是两个选择：休息，或者十分钟后再问一次（snooze 只改下一次的倒计时，不动间隔设置）。

**锁屏（Ctrl+Alt+L）**：全屏不透明遮罩 + 时钟；密码存在**加密凭据库**里（保留 id，不进 settings、不回传渲染进程），只提供「设置/校验」，渲染进程永远拿不到明文。密码可以是空的——那就是点一下解锁；也可以随时清空。

诚实边界：锁屏只是**挡住屏幕**，不暂停会话、不加密磁盘上的 profile，也不防拿到这台机器的人。

验证：`smoke:drawer` + `smoke:wellbeing`；两套都在第24轮扩过（见下）。

## ✅ 第24轮：抽屉的手感 / 历史命令按 session 存 / 专注模式 / 删掉小游戏

**抽屉顶部的 Connect 与 Local shell 一行删掉了。** 它们占据的是页面上最值钱的位置，而两件事都可以更省地方：现在是抽屉底部的一排图标（`＋` 新建连接、`>_` 本地 shell、`⧉` 连接窗口、`⌨` 快捷指令栏、`⚙` 设置）。本地 shell 没有别的入口，所以它必须有一个可见的家，而不是趁人不注意藏起来。

**每个标题前有折叠三角**：点一下把内容折起来，只留标题。折叠**不是隐藏**——位置、隐藏菜单、设置页的勾选框都不动，它只是「先收一下」。三角在拖拽手柄里面，所以它的 click 会 stopPropagation，点它不会顺手拖动分区。

**分区高度、抽屉宽度都可以拖**：分区底边是高度手柄（双击恢复自适应），抽屉右缘是宽度手柄。两者都在**拖动过程中只改本地 state、松手才落盘**——一次设置保存要写文件并向所有窗口广播，不能每移动一个像素就来一次。落盘后进 `settings.sidebar`（`sections[].height`、`width`），因此重启后还在；手改配置文件也会被 clamp（宽度 200–560，分区高度 80–720）。

**历史命令改为「每个 session 一个文件 + 保存 7 天」**：`history/<sessionId>.json`，每条最多 200 条、单条最长 500 字符，连续重复忽略；**过期清理在启动时做**（应用不会连续开一周，挂在定时器上永远不会触发）——最新一条超过 7 天的文件整个删掉，文件内部的旧条目也一起清。面板默认跟着**当前窗格**，并且有一个下拉可以翻看任何还在 7 天窗口内的 session（关掉一小时的会话仍然读得到），列表底下写着「Kept for 7 days, per session」。


## 🧰 探针卫生（第23轮补充）

`scripts/checkprobes.cjs` 现在还会检查**注入模板里的转义**：模板字符串会吃掉反斜杠，`/^\//` 到了渲染进程就变成 `/^//`（语法错误，而 `executeJavaScript` 只报「Script failed to execute」），`\s`/`\d`/`\w` 则变成普通字母、正则静默变味。检查只扫模板内部（普通代码里的正则不受影响），允许 `\n`/`\r`/`\u001b`/`\$` 这些有意为之的转义。它第一次跑就抓到了 `snippet.cjs` 里两处 `\s*`（碰巧因为 `s*` 可匹配零次而没暴露）。

一个它抓不到的坑，第25轮又踩了一次：**模板里写正则时连 `\n` 都不能用**——`[^\n]` 会变成「`[^` + 真换行 + `]`」，正则字面量里出现真换行是语法错误。检查器允许 `\n` 是因为绝大多数探针用它拼字符串，所以这类只能靠人：探针里需要「到行尾」时用 `indexOf` + `String.fromCharCode(10)` 切，而不是正则。

第三类问题是**合成事件不够真**，第29轮一次踩了两处。「派给谁」和「事件内容」都要对：

- **拖拽要按坐标派发到指针底下那个元素**（`document.elementFromPoint(x, y)`），不要直接派给目标元素。旧版 `smoke:drawer` 把 drop 直接派给抽屉，坐标根本不参与，于是「拖到工作区那一侧」这个真实手势永远做不到的交互也能报绿。
- **按键要带真实 `keyCode` 和修饰键**。xterm 是按 `keyCode` 分派的，只给 `key` 的合成 `KeyboardEvent` 会被它当成 keyCode 0 直接忽略、事件照常冒泡到 window——快捷键测试报绿，而真实按键会被 xterm 拦下（`stopPropagation` + 往 shell 发 ESC 序列）。派发对象也要选 `document.activeElement`（终端真的持有焦点时才会走到那条路），并顺手断言「焦点确实在终端里」。

## ⚠️ 已知边界

- Termius 是闭源软件：**未复制其任何代码或素材**，仅参考通用布局模式。
- `setZoomFactor` 是**异步**生效的，且缩放**不改变容器 CSS 尺寸**，因此 ResizeObserver 不会触发。两处一起出问题：改缩放时若正好有窗格在首次布局中，dockview 会量到中途尺寸并把栅格钉在 100×100（窗格塌成约 65px、终端空白）。应对：① 渲染进程**不在首次渲染时**推送缩放，改由主进程在窗口显示前应用；② 所有缩放变更（含设置抽屉的即时预览）统一走 `applyUiScale`，落地后重新断言一次布局。`smoke:repeat` 交替跑「普通启动」和「运行中改缩放」两条路径。
- macOS 字体枚举未实现，会退回内置短名单。
- 密码型首次连接的「是否保存密码」提示未端到端验证（缺少密码；走的是同一条已验证的加密路径）。
- 探针依赖 `82.156.226.192` 作为 SSH 目标，可用 `TD_SSH_HOST` / `TD_SSH_USER` / `TD_SSH_KEY` 覆盖。
- **已知：`smoke:features2` 仍会偶发失败**（约一半的运行），症状是「标签页右键改了 showTimestamps 设置之后，终端回到 80×24、时间戳列全空」。已确认不是应用主路径的问题：同一时刻 `smoke:repeat`(8/8)、`smoke:scale`(5/5)、`smoke:chrome`(25/25) 都是稳的，只有这一套在**它自己保存设置之后**复测时出现。下一步要查的是「设置变化时终端是否被重建、重建后谁负责再次 fit」（`TerminalPanel` 的 `useTerminal` 以 `session?.id` 为依赖，理论上不该重建）。不要为了让这一套变绿去放宽它的断言——那会把真实回归一起盖掉。
- 时间戳取的是 xterm `onWriteParsed` 之后的缓冲（在 `write()` 之后立刻同步会读到写之前的缓冲，整列时间戳永远是空的）；列宽由一条真实渲染的隐藏时间戳量出来，而不是用 em 估算——估窄了会把右括号裁掉，而 `overflow: hidden` 让这件事只表现为「时间戳少一截」。
- **探针测到的「窗格 65px、终端空白」还有第二种来源：被遮挡的渲染进程被 Electron 节流。** 节流中的渲染进程会返回**过期的 computed style**（`inline width:1124px` 而 computed 是 `100px`），并且根本不绘制，于是 xterm 永远量不到 cell、`fit()` 直接空转，`term.rows` 停在 24。这不是应用的状态（用户看见的窗口是好的），`dock.layout()`、`forceRelayout()`、改容器尺寸都救不了它；给探针窗口加 `webPreferences.backgroundThrottling: false` 后，同一套件从「约一半运行失败」变成连续 3/3 通过，首窗格稳定 1110x779。`smoke/chrome.cjs` 已加上该标志，`smoke/panestep.cjs` 的「重载重试」保留作为兜底。
- 探针脚本里的注入代码是模板字符串，**反斜杠转义与反引号都不可靠**：写 `\d` 会变成字母 `d`（正则静默匹配不上，看起来像功能坏了），注释里的反引号会提前结束字符串。所以探针里用字符判断代替正则，并且 `node scripts/checkprobes.cjs` 会在跑套件前先解析一遍所有探针（解析失败在套件里只表现为「卡住不动」）。
- **`smoke:wellbeing` 依赖真实前台焦点**（第30轮踩到）：它的番茄/提醒定时器只累计 `document.hasFocus()` 为真的秒数，而 `win.focus()` 只是给 Windows 的请求 —— 后台进程不一定抢得到前台，于是同一份构建连跑两次会得到 46/46 和 37/46。它现在先等焦点、等不到就一条 FAIL 退出。跑这一套时别在别的窗口里操作。
- 本机 Windows 的「动画效果」是关的，Chromium 因此报 `prefers-reduced-motion: reduce`，而 `global.css` 里两条全局规则会把所有过渡/动画压成 1ms：**这台机器上看不到任何动画**，`smoke:gesture` 里那半边关于侧栏宽度过渡的断言因此要靠 `Emulation.setEmulatedMedia` 临时把偏好改成 `no-preference` 才能观察。

## 💤 休息提醒：第25轮的做法

第23轮那个 2D 小游戏删掉了（比它要解决的问题更烦人，而且它 bug 多的根源是「模态里抢键盘 + 自己写物理 + rAF」，探针甚至只能靠调试钩子作弊通关）。现在的做法是「1+2+4」：

1. **不打断**：一条横条挂在终端上方（在布局里，不在上面浮着），占一行，不抢键盘、不遮挡输出。
2. **等空闲**：`break.idleSeconds`（默认 5 秒）内任何会话都没有输出才出现。信号就是 `session:data`——命令在跑、或者你在打字被 shell 回显，都算「忙」，所以它绝不会落在你正敲的那条命令上。`smoke:wellbeing` 真的跑了 70 秒连续输出断言「不出现」，再停下来断言「出现」。
3. **休息并锁屏 + 记录**：三个动作分别是「休息并锁屏」（复用锁屏盖住屏幕，这才是真的起身）、「已经休息」、「N 分钟后再问」（snooze 只把下一次的倒计时往前挪，不动间隔设置）。每次休息把**本次连续工作时长**写进 `settings.breakStats`（最长一次 / 次数 / 上次时间，重启后仍在），并在 Logs 页留一条 `Break taken after N min of continuous work`。

## 🍅 第26轮：番茄循环 / 抽屉停靠右侧 / 底部按钮固定

**番茄循环**（`break.mode = 'pomodoro'`）与提醒共用同一个计时器和同一道空闲门：

- 一个循环两段：`minutes` 分钟的工作轮 → `breakMinutes` 分钟的休息。工作那一段**只算窗口有焦点的秒数**（和提醒一致），所以走开了就不算数；休息那一段是**墙钟时间**——休息的意义就是你离开键盘，要求焦点才能倒计时等于在你做对的时候把表停下。
- 工作轮到了之后**不立刻打断**：等那道空闲门（所有会话安静 `idleSeconds` 秒）通过才切到休息，并且**休息从这一刻开始计时**，否则「命令跑着的时候休息已经偷走了两分钟」。
- 横条按三种状态说话：`reminder`（提醒）、`break`（休息中，带倒计时）、`work`（休息结束，开始下一轮）。倒计时只让横条和抽屉那个小胶囊自己每秒重渲染，App 本身只在**换段**时重渲染。
- 抽屉底部有一个 🍅 胶囊显示「工作轮长度 / 休息剩余时间」（点它进设置）。设置页 Wellbeing 里可以切换模式、改工作/休息长度，并显示累计（含完成的番茄轮数）。
- 提前结束休息**也会记录这一轮**：工作确实发生了，因为休息被截断就把它丢掉会让计数说谎（这是 `smoke:wellbeing` 抓出来的）。

**抽屉停靠到屏幕右侧**：底部那排图标里有一个 `⠿` 把手，把它拖到窗口的**另一半**松手，整个抽屉就停靠过去（rail 在最左、工作区在中间、抽屉在最右）；再拖回来即可，**双击把手**直接翻面。落点只按指针在窗口的哪一半决定——抽屉只有两个位置，没必要问「拖到中间算哪边」。停靠侧写进 `settings.sidebar.side`，重启后仍在；停靠右侧时宽度手柄自动挪到抽屉**左缘**，拖拽方向也随之反向。分区标题的三角与动作按钮在右侧停靠时会镜像到靠内容的一侧。

**底部按钮固定在底部**：抽屉改成「固定列 + 中间可滚动的分区容器 + 不滚动的页脚」。之前整个抽屉一起滚，四个分区都展开时那排图标会被挤到抽屉外面够不着。验证方式是**故意把四个分区都设成 400px** 制造溢出，然后断言页脚仍在抽屉框内且位于下半部（`smoke:drawer`，50 项）。

## ⌨️ 第27轮：广播按钮去掉数字 + 页面快捷键

**广播按钮不再显示窗格数**。它本来就悬在它所描述的那几个窗格上方，「all 3」是在把人已经看见的东西再念一遍；数字留在 tooltip 里。`smoke:features3` 断言按钮文本里没有数字、`.td-broadcast-count` 不存在、tooltip 里仍有 `N panes`。

**页面快捷键**分两族，共用同一条路径（`selectPage`），所以快捷键与点击绝不会对「Terminal 是哪个」有不同理解：

- `Alt`+数字直达 rail 上的第 N 项（1 Terminal · 2 Hosts · 3 Known Hosts · 4 Snippets · 5 Logs · 6 Settings）。**这一族不是九行设置**：哪个数字对应哪个栏目是 rail 的顺序，不是偏好——它是用来记住的，不是用来配的。设置页 Shortcuts 里有一行只读说明。
- `Alt+[` / `Alt+]` 前后切换**并首尾循环**（Logs → Terminal，Terminal → Logs），这两个是正常可配置的按键项。它们走的是 `PAGE_CYCLE`（五个有页面的栏目），**不含 Settings**：Settings 是盖在任意页面上的抽屉，循环里停在那里会看起来像「按了没反应」，它另有 `Alt+6` 和 `Ctrl+,`。这一点是探针发现的——第一版按 `Alt+[` 从 Terminal 往后走会打开设置抽屉，断言直接把它抓出来了。

**为什么顺手移除了应用菜单**：默认菜单平时看不见，但**按 Alt 会把它顶出来**，而每一个 Alt 系列快捷键都会连带触发这件事——菜单栏一出现，整个布局就往下跳，松手才恢复。所以主进程里 `Menu.setApplicationMenu(null)`（`src/main/shortcuts.ts`），开发用的两个加速键（F12 / Ctrl+Shift+I 开发者工具、Ctrl+R 重载）**只在非打包构建里**用 `before-input-event` 补回来。`smoke:nav` 直接断言 `Menu.getApplicationMenu() === null` 且 `win.isMenuBarVisible()` 为假。

验证：`smoke:nav`（13 项：rail 顺序、Alt+1/2/4/6、越界忽略、`Alt+[`/`Alt+]` 单步、两端循环、无菜单/无菜单栏）。

## 🔤 第28轮：界面字体与文字排版

**退出弹窗「文字顶到边框」的真因**：`.td-modal` 本身没有内容内边距——带表单的模态看起来正常，是因为 `.td-form` 自带 `padding`；而退出确认这种「标题 + 几段 `<p>` + 底栏」的模态，正文就真的贴着边框画。所以加了一个共用的 `.td-modal-body`（`padding: 16px 20px`、`gap: 10px`），并把标题/底栏保持整宽出血。`smoke:type` 是**量出来的**：正文左右各留 21px、两段之间 10px、标题栏与底栏仍然横跨整个弹窗（不是只看一眼截图）。

**界面字体换成自带的 Inter**（SIL OFL 1.1，只带 latin 子集 400/500/600/700，共约 94 KB，许可证和字体文件放在一起）：

- `--td-font-ui` = `'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI Variable Text', 'Segoe UI', system-ui, sans-serif`。**Inter 排在系统字体前面**是有意的：它长得像 SF，而且是自带的，所以三个平台的界面完全一样——之前用「系统 UI 字体」的结果就是同一个界面在 Windows 和 macOS 上不一样。
- **它不跟随终端的字体设置**，这一条是被断言的而不是被声称的：`smoke:type` 把 `terminal.fontFamily` 改成 `"Comic Sans MS"`，然后断言**终端**（`.xterm-rows` 与 `term.options.fontFamily`）跟着变、**界面**（`body` 与抽屉标签）仍然是 Inter。终端的字体是终端的。
- 等宽仍然用于**数据**而不是装饰：指纹、SFTP 路径、时间戳列、命令历史、快捷键录制框。`--td-font-mono` 里加了 `'SF Mono'`，macOS 上会优先用它。
- 顺手修掉了**合成加粗**：原来有 `font-weight: 620/640`，而我只带 400/500/600 —— 浏览器会自己糊一个假粗体。现在带上了真实的 700（`<b>` 用），并把 620/640 归一为 600。

**字号/行高归一**：新增一套 token（`--td-text-2xs/xs/sm/base/md/lg`、`--td-leading: 1.55`、`--td-tracking-label`），把最显眼的几处收进来——之前同一个「小标题」在三个页面分别是 11px/0.6px、10px/0.9px、12px/0.6px，`body` 也没有设 `line-height`。`body` 现在按 Inter 的推荐设了 `letter-spacing: -0.006em` 和 1.55 行高，设置页的标签列也从 150px 加宽到 172px（Inter 稍宽，"Credentials" 会被挤到第二行）。

验证：`smoke:type`（12 项，含上面那些测量）。

## ⌨️ 第29轮：快捷键切的是**会话** / 缩放快捷键 / 抽屉停靠的真因

三个要求：`Alt`+数字与 `Alt+[` `Alt+]` 要切换**会话窗口**（不是栏目）、抽屉要能拖到工作区那一侧停靠、新增 `Ctrl`+`=` `Ctrl`+`-` 缩放。

**会话快捷键。** `Alt`+数字是第 N 个**打开的会话窗格**（dockview 的标签顺序就是 1、2、3…），越界直接忽略——这一族不是九行设置，数字是排布的位置，它是用来记住的、不是用来配的（`Alt+6` 顺便不再打开设置）。`Alt+[` / `Alt+]` 是上一个/下一个**会话**，**跨分组**（`Ctrl+Tab` 只在一个分组内走）并首尾循环；停在欢迎页时第一次按会落到第一个（向后）或最后一个（向前），所以没有「按了没反应」的第一下。`NavRail` 里的 `PAGE_ORDER` / `PAGE_CYCLE` / `PAGE_LABELS` 随之删掉——留着只会和 rail 漂移。

**缩放快捷键。** `Ctrl`+`=` / `Ctrl`+`-` 走 `UI_SCALES` 这条阶梯（70/80/90/100/110/125/150/175/200%），落盘 `settings.uiScale` 并弹一条 toast；到顶/到底只提示，不再改。设置页的尺寸芯片改成**同一条** `UI_SCALES`：之前芯片是另一套更短的列表，快捷键能落在一个没有任何芯片高亮的尺寸上。`Ctrl`+`Shift`+`=` 是「真正打出一个 `+`」的按法，数字键盘也一样，这两条在渲染进程里补——一个按键字符串表达不了「两个都行」。`Ctrl`+`Alt`+`=` **不**缩放：带 Alt 的那一族属于会话。

**抽屉「拖到右侧没反应」的真因。** drop 目标原来挂在那个 268px 宽的 `<aside>` 上；真实拖拽时指针早就在工作区上方，drop 落在 `.td-content` 上，而它不是抽屉的一部分，所以抽屉永远收不到。现在 drop 处理挂在 `.td-root`（整窗），把手与分区标题（`draggingDrawer || draggingSection`）都算「一次停靠正在进行」，**指针在窗口哪一半就停哪一边**；分区标题自己的 `onDrop` 加了 `stopPropagation`，否则「把 A 拖到 B 前面重排」会同时被当成一次停靠。双击把手改为直接翻面，分区右键菜单新增 **Move drawer to the … side**——不想拖的人也有确定的一条路。

**探针顺手抓出来的两个真问题**（都修在应用里，都不在原计划里）：

- **切窗格会把键盘丢到 `body`。** dockview 隐藏旧窗格，而被隐藏的元素留不住焦点：`Alt`+数字切过去之后，你打的下一个字谁都收不到。新增 `activatePanel()`，**只有**当按键前焦点就在终端里时才把新窗格聚焦（在设置输入框里按 `Alt+[` 不会把光标抢到后面的窗格去）；`Ctrl+Tab` 走同一条路。
- **xterm 把 `Alt`+数字 / `Alt+[` / `Alt+]` 吃掉了。** xterm 在 window 之前拿到按键，对它处理的键会调 `stopPropagation`，所以窗口上的监听器**根本收不到**——快捷键恰好在「你真正要按它的地方（终端里）」完全无效。而且它把这些键当成「Alt+字符」，会往 shell 里发 `ESC 2` / `ESC [` / `ESC ]`；其中 `ESC ]` 打开一个 OSC 字符串，之后敲的字符全被行编辑器吞掉，直到收到终止符。修法是 `term.attachCustomKeyEventHandler` 把这一族让出去：xterm 既不发送也不拦。

这两个都是**探针自己不够真**才浮出来的：只给 `key`、不给 `keyCode` 的合成 `KeyboardEvent`，xterm 会按 keyCode 0 直接忽略（事件于是照常冒泡到 window，探针报绿），而真实按键走的是另一条路。`smoke:nav` 现在带真实 `keyCode`，并在按键前断言「焦点在终端里」。

验证：`smoke:nav` 16 项（3 个本地 shell、`Alt+1/2/3` 各自命中、越界忽略、单步与两端循环、**rail 一直停在 Terminal**、按键时焦点在终端、切完焦点仍在终端）；`smoke:scale` 35 项（新增阶梯步进 / 落盘 / 别名 / `Ctrl`+`Alt` 不缩放 / 到顶停止，且这些按键都在**焦点位于终端**时按下）；`smoke:drawer` 59 项（停靠的三条路径：把手拖到工作区、分区标题拖到另一半、右键菜单；drop 一律用 `elementFromPoint` 派发，并断言**落点确实在抽屉之外**）。

## 🧩 第30轮：批量加主机 / 密码被拒单独弹窗 / 分组名居中弹窗 / 提示文字排版 / 拖拽期间不再逐帧 fit

三个要求：新增 hosts 要能**批量**（一个模式开关，密码默认覆盖所有 session，某台连不上时单独弹窗重输）、新建与重命名分组要**弹出输入框**（且居中）、界面字体参考 Termius 且动效更顺。

**批量添加。** 解析是纯函数，放在 `src/shared/batchHosts.ts`，探针直接驱动它（`smoke:batch` 的前 11 项）。规则是「一行一台 + 一条尾号区间规则」：`#` 注释、逗号/空格/换行分隔、`user@host:port`、`ssh://` 都认；区间只按「**尾号在动**」判定 —— `10.17.20.210-215`、`node01-04`、`10.17.20.210-10.17.20.215` 都能展开，而 `web-1.example.com` 因为「短横前必须以数字结尾」不会被误判成区间。**倒着写的区间报错，不当成主机名**：`10.17.20.215-210` 否则会静默变成一台叫这个名字的主机，这种笔误要到很久以后才会被发现。上限 256 台，超了截断并明说；同一份粘贴里的重复主机只算一次；读不出来的 token 连原文一起报出来。表单里有一行**预览**：「6 hosts will be added · 6 already saved, skipped · 1 could not be read (nonsense:99999: port out of range)」—— 悄悄变短的列表才是用户无从核对的东西。

「已经存在」按**主机 + 用户名 + 端口**判定，而不是只按主机：同一台机器用两个账号登录是正当的两条会话（`smoke:batch` 里专门有一条断言，避免这个判断被改成「按主机去重」）。

**共享密码 = 每台各存一份密文。** 批量保存走新的 `session:saveSessions` / `SessionStore.addSessions`：一次写入、一次广播（`upsertSession` 原本每调一次就写文件并广播整棵树，20 台就是 20 次），密码按每台自己的 id 分别封存 —— 这就是「覆盖所有 session」的含义，而「某台密码不对」也就只是那台的事。

**密码被拒 → 直接弹那一台的密码框。** 真因是主进程把「认证失败」和「连不上」说成了同一句话：`SshShellBackend` 的 `client.on('error')` 把 ssh2 的错误 `describeError()` 成字符串后 `new Error(...)`，`level: 'client-authentication'` 就此丢失。现在这类错误打上 `AUTH_FAILED` code（`serialiseError` 也改成透传任何字符串 `code`，此前只认 `HostKeyRequiredError`），渲染进程看到它、且该会话是**密码认证**时跳过 alert 那一步，直接把居中的密码框开给这一台 —— `smoke:ui3` 断言弹窗里写着这台会话名与 `user@host:port`。密钥 / agent 的失败不走这条路：再输一遍密码修不好它们。

**分组名弹窗居中。** 三个入口（Hosts 页头新建分组、抽屉树的分区标题、树上的 ⊞）以前各有各的做法，其中抽屉那一路用的是 `window.prompt` —— Electron 渲染进程不支持它，所以**那一路什么都不发生**。现在都收敛到 App 里一个居中的 `NamePrompt`：新建分组先问名字（不再先生成一个 "New folder" 再让你改），重命名预填原名并全选。`smoke:hosts` 里还装了 `window.prompt` 的**绊线**：整套跑完再断言没有任何命名流程回退到浏览器 prompt。

**提示文字排版的真因。** 密码下面那行说明渲染成了大写、加粗、宽字距，因为 `.td-field > span` 把字段里**每一个直接 span** 都当成 overline 标签排版，而 `.td-hint` 正好是其中一个 span。给 `.td-hint` 加回 `font-weight: 400` / `text-transform: none` / `letter-spacing: normal`，并把两处「事后覆盖」`.td-field > span` 的补丁（10.5px / 0.6px）并回原规则，免得下次又被覆盖一次。

**「搓顿感」的真因不是过渡，而是每帧都在重新 fit。** 尺寸一变就 `doFit()`：测量窗格 → xterm reflow → 通过 IPC 让主进程 resize pty。窗口缩放时这是对的，拖分屏条时就是灾难 —— 一次手势三十帧就是三十次 pty resize。新增 `setFitsPaused()`：拖分屏条、拖标签页（dockview 的 HTML5 拖拽）、拖抽屉边缘、以及侧栏宽度那段过渡期间**都不发 fit**，手势结束后 `refitAll()` 一次。这件事从外面看得见（`window.__tdFitsPaused` 与 `.td-root.is-layout-gesture`），`smoke:gesture` 18 项：折叠侧栏时「识别为手势 → 期间 cols 不动 → 结束后 172→175」，以及**切换页面和点标签页不算手势** —— 过度暂停比不暂停更糟，那会把终端永久冻在手势中间那个尺寸上。

**关于动画：这台机器上根本没有动画。** 实测 `matchMedia('(prefers-reduced-motion: reduce)') === true`（Windows 的「动画效果」是关的），而项目里早就有两条全局规则把**所有**过渡与动画压成 1ms。所以动效这半边只做了一件不增加动画的事：加 `--td-dur-fast` / `--td-dur-base` / `--td-ease-out` 三个 token，把散在各处的 28 处 `110/120ms ease`、7 处 `140/160ms ease` 收进去（原来同一个界面里 `ease` 和 cubic-bezier 会相邻出现）。我先做了抽屉退出动画与页面/弹窗/窗格淡入，按「不需要动画」的要求**全部撤回** —— 卡顿的修复和动画无关，它在于每帧少做工作，不在于多画一层过渡。

**页面顶部改成参考应用的形状。** 原来列表页的头是「大标题 + 统计」在左、搜索框和按钮挤在同一行右侧（搜索框固定 240px）。现在按参考应用那两行来：第一行是**通栏的筛选条**（左侧自绘放大镜 —— 应用其它图标都是 Unicode 字形，而放大镜那个字形基线和旁边的字不一样高，会变成每页第一行都在抖），第二行左边是页面动作、右边是统计和视图开关（Rows/Cards 改成只有图标）。页面标题**只留给读屏**（`.td-sr-only`）：rail 已经说明这是哪一页，再画一遍要占掉屏幕最高区域的整行；四个列表页（Hosts / Known Hosts / Snippets / Logs）共用这套结构，标签筛选也从单独一行挪进动作行。

**探针教训：`smoke:wellbeing` 依赖真实前台焦点。** 它的定时器只累计**聚焦**秒数，而 `win.focus()` 只是个请求 —— Windows 不保证后台进程能抢到前台。同一份构建连跑两次拿到 46/46 与 37/46，后者是九个计时断言连锁失败（我一度以为是自己改坏了，用 `git stash` 回退到干净提交对比才发现两边都会随机失败）。现在它先等前台焦点，等不到就只报一条 FAIL 并立刻退出，不再让人对着九个失败猜原因。

验证：`smoke:batch` 30 项、`smoke:gesture` 20 项（**新增两套**）；`smoke:hosts` 38 项（新增居中弹窗与 prompt 绊线）、`smoke:features` 99 项、`smoke:ui2` 53 项（新建分组先问名字）、`smoke:ui3` 50 项 / `smoke:ui4` 38 项（密码被拒直接弹框、且写明是哪一台）；`npm run verify` 全绿（31 套）。
