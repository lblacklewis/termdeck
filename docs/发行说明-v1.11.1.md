# TermDeck v1.11.1

## 修复

**重连现在真的在后台做：不抢焦点、不弹红条**

以前自动重连成功会把那个窗格**切到前台**——你正在 A 节点敲命令，后台的 B 节点重连成功，光标
就被拽走了。另外重连**失败**会弹全局的红色「连接失败」条。

- 重连**不再激活窗格**（`bindSessionToPanel` 多了 `activate` 参数，重连传 `false`）；
  用户自己点「连接 / 重连」这类显式动作仍然照旧激活。
- 重连失败的**原因显示在那个窗格自己的遮罩上**（红字，就在「重连」按钮上方），不再弹全局提示条。
  失败原因若是主进程给的可编码错误（`NOT_RECONNECTABLE`），渲染端翻成中文，其余照原样显示。
- 后台重连成功时页面上**什么都不弹**。

**重连回来之后 vim 只有半屏 —— 找到真因并修掉**

这是个货真价实的尺寸 bug，不是 vim 的问题：

1. `session:resize` 只把新尺寸转发给会话，**没有更新 blueprint**；
2. 而重连（以及"重建这个会话"的每条路）都是**按 blueprint 记的 `cols/rows`** 去建新 PTY 的；
3. blueprint 里存的还是**会话刚创建时**的尺寸 —— 也就是 80×24；
4. 渲染端只在尺寸**变化**时才发 `resize`，重连没有改变窗格大小，于是**永远没人纠正**。

结果：窗格已经 138×41 了，重连回来的 PTY 还是 80×24 —— 全屏程序按 80×24 画，右上和下方各空出一块，
看起来就是「vim 只有半屏」。探针在修之前实测到 `before={"cols":138,"rows":41} after={"cols":80,"rows":24}`。

修法两处：

- **主进程**：`session:resize` 顺手把新尺寸写回 blueprint（连接已经断开时也写，掉线期间调整窗口也算数）。
- **渲染端**：`useTerminal` 新增 `resendSize()`，会话对象被替换（重连）时**无条件**再推一次尺寸。
  「没变就不发」那条判断是为省流量写的，这里恰恰需要"没变也发"。

顺带确认了**历史仍然保留**：同一个 session id 重建，主进程的滚动缓冲区不动
（探针里 `replaySession` 仍能读到断开前打的那行标记）。所以"不保存历史信息"那个退路**不需要用**，
窗格也仍然是原来那个窗格，没有新开窗口。

## 探针里踩的坑（记录）

1. **探针模板里又出现反引号**（注释里写了 `.xterm-rows`），把模板字符串提前闭合，报
   `rows is not defined` —— 那条铁律是有用的。
2. **`window.__tdTerminals` 只存活的终端**：隐藏的 tab 会被 dockview 卸载，终端元素不在 DOM 里，
   所以"历史还在不在"必须查**滚动缓冲区**（`term.buffer.active` + `getLine(i).translateToString`），
   不是 `.xterm-rows`（那只有视口）。
3. **重连回来的 shell 自己会清屏**（cmd 启动就发擦屏序列），所以"屏幕上还有旧内容"根本不是 TermDeck
   能保证的事 —— 该断言的是**回放数据还在**。
