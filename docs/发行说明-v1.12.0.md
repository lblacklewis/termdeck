# TermDeck v1.12.0

## 新增：输出高亮（关键词 / IP / 链接上色）

终端里一屏字里，真正要看的往往就几处：地址、链接、错误词。现在它们可以被上色，
类似 oh-my-zsh 的配色，也提供 XShell 那种**色块**风格。

**默认关闭**：设置 → 终端 → 「把输出里的地址、链接、错误关键字上色」。打开后可以：

- **选配色方案**（4 套，切换即时生效）：

  | 方案 | 风格 |
  | --- | --- |
  | 经典 | 亮色前景，oh-my-zsh 那一挂，适合深色主题 |
  | XShell 色块 | 前景+背景成块，深浅主题都清楚 |
  | 柔和 | 中等色调，适合浅色主题 |
  | 单色 | 信息类同一个颜色，不爱彩虹的人用 |

- **逐条开关**，8 条规则：IP 地址、链接、邮箱、MAC 地址、文件路径、错误关键字、警告关键字、成功关键字。
  默认开 7 条，**文件路径默认关**（`~/.config/...` 这类太多，最吵）。
  每条规则旁边有个 `Aa` 色块，直接显示该方案下的真实配色，不用先应用再猜。

匹配是按行正则：`10.20.30.40` 只框 11 格，`failed` 只框 6 格 —— 不会把整行刷掉。
规则按顺序匹配，**先匹配上的格子归它**：链接里有斜杠，所以 `path` 不会去重刷链接的内部。
vim 里（alt buffer）不上色。

## 复制出去的仍然是纯文本

这是刻意保证的，也是这套实现选型的原因：**高亮用 xterm 的 decoration（给单元格上色），
不往数据流里塞 ANSI 转义序列**。

如果改成"把匹配到的词包上 SGR 颜色码再写进终端"，列宽计算、折行、光标位置全会错乱，
而且那些颜色码会顺着复制/粘贴流到下游 —— 这正是要避免的。现在的做法下：

- 缓冲区里的文本一个字节都没改；
- `复制`、`复制整屏`、`保存输出`、`导出` 拿到的都是**远端发来的原样文本**，不含任何 ESC/OSC 序列；
- 探针里就是这么断言的：开着高亮复制整屏，检查文本里没有 `ESC`，且 IP、链接、单词原样在。

顺带确认了一件事（软件本来就这样，这次加了断言把它钉住）：**折行的长行复制回来仍然是一行**，
xterm 不会在折行处插换行符。

## 实现上踩到的两个真事实（记录，免得下次又猜）

1. **颜色不在 decoration 元素上**。xterm 的 DOM 渲染器把 decoration 的颜色**烘焙进行内的 span**，
   而且**一个字符一个 span**（`<span style="background-color:#1864ab;color:#d0ebff;">1</span>` × 11），
   decoration 那个 `<div class="xterm-decoration">` 自己只有位置和宽高、背景是透明的。
   所以"验证颜色对不对"只能读那些 span 的计算样式；探针现在数的是
   **该行里带某配色的字符 span 个数**，个数正好等于匹配长度 —— "IP 是蓝的"和"正好 11 个字是蓝的"
   于是成了同一条断言。
2. **设置项要放平，不要嵌套**。`mergeSettings` 对 `terminal` 是**浅合并**
   （`{...defaults.terminal, ...stored.terminal}`），嵌套对象会被整体替换掉，
   `{enabled:true}` 会把同级的其它字段一起弄丢。所以高亮设置是三个平铺字段
   （`highlightEnabled` / `highlightScheme` / `highlightRules`），另外补了 `mergeTerminal`
   校验规则 id 列表 —— 手改配置文件写进不存在的 id 会被丢掉，
   而**列表缺失**要理解成"用默认的"，不能理解成"一条都不开"（不然开关打开了却什么都不亮，
   看起来像功能坏了）。
