# TermDeck v1.11.0

## 新增

**主机页可以勾选批量操作：删除 / 复制 / 移动到分组**

以前只能一台一台来（右键菜单），要整理十几台机器就得点十几次。现在：

- **每台主机前面有勾选框**（行视图和卡片视图都有），页面左上角有 **全选**；
- 勾上任意一台，页头下面出现**批量操作栏**：`已选 N 台` · **移动到…** · **复制** · **删除** · **取消选择**；
- **移动到…** 弹出菜单列出**所有分组**（含嵌套的完整路径）和 **未分组**，一步改完；
- **复制**给每台生成一份「名字 copy」，留在原分组，**连保存的密码一起带过去**（用新 id 重新加密），
  复制出来的主机不用重输密码就能连；
- **删除**是两步：先问一次「删除 N 台」，确认才真删；**每台被删主机的密文也一起清掉**，不留孤儿。

三条实现上的选择（都在交接文档里）：

- **一次写盘**：三个批量操作各走一次主进程调用（`tree:deleteSessions` / `tree:duplicateSessions` /
  `tree:moveSessions`），store 里各只 `commit` 一次。循环调用单台接口的话，选二十台就是**二十次写
  `sessions.json`、二十次广播、二十次重绘**，列表会一边点一边抖。
- **"全选"= 屏幕上看得见的那些**。折叠起来的分组不算：把看不见的主机勾进一个随后会被删除的选择里，
  正是批量操作最不该有的意外。筛选和折叠都会实时把已消失的勾选清掉。
- **勾选是临时状态**，存在页面里（不是 `layout.json`）：离开页面就清空。带着十分钟前的勾选回来，
  是删错东西的经典路径。
- 批量操作**做完就清空选择**：刚复制/移动完的主机已经不是勾选时的那批了，留着勾选会让下一次点击
  打在用户已经不看的东西上。

## 验证

新套件 `smoke:hostsbatch`（**18 条**，读真实 DOM 与真实存储），已进闸门。先写在**未改动的代码**上跑：
**14 条里 13 条 FAIL**（唯一通过的是"主机页能打开"）。

覆盖：

- 每台主机都有勾选框；勾一台出现批量栏与计数；能取消选择；
- **全选勾满整页**；**折叠一个分组后全选只勾屏幕上那 4 台**（折叠里的 `web-1` 不被勾上）；
- **移动**：菜单列出全部目标，选一个之后两台主机的 `parentId` 都变了、页面也把它们画在新分组下；
- **复制**：正好多出两台、名字是 `X copy`、留在原分组，**并且 `revealCredential` 能读到原密码**；
- **删除**：先出现确认、此时一台都没少；**取消后一台没少**；确认后正好少勾选的那些；
- 删除的主机**密文也没了**（`revealCredential` 返回 null）。

**探针里踩的坑（都是探针自己的）**：

1. `upsertSession` 和 `upsertFolder` 一样，返回的是**整棵树**而不是新建的对象，`.id` 永远是
   `undefined` —— 于是所有选择器都落空，探针失败的原因和功能毫无关系；
2. 先取"删除"按钮、再勾选：批量栏只在有勾选时才存在，所以守卫顺序反了，最后一条永远走不到；
3. 把"功能缺失"的分支都写成显式 FAIL，而不是让断言被 `if` 悄悄跳过 —— 否则旧实现上只会看到
   一两条失败，看不出到底哪些承诺没兑现。
