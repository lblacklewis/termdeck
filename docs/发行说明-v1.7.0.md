# TermDeck v1.7.0

## 改进

**REST 页面不再是一条长页**

以前请求在上面、**响应在下面**：想看结果就得先滚过自己刚敲的东西。现在这一页自己不动了，左右各管各的：

- 左边一列：**历史**与**已保存**，各自独立滚动；
- 右边上面是请求表单，下面是响应；
- 请求区最多占屏幕的 42%，超出部分自己滚 —— 所以正文再长，**响应都不会被挤出屏幕**；
- 响应在自己的框里滚动。

实测（探针断言，不再是感觉）：页面本体 `scrollHeight == clientHeight`（不滚）、响应的框上下沿都在窗口内
（top 534 / bottom 822，窗口 883）、响应自己 `scrollHeight > clientHeight`（内部滚）。**正文塞进 40 行之后
响应框位置不变**（bottom 仍是 822），换成表单自己滚（330 / 313）。最后这两条正是旧版会失败的地方。

## 新增

**请求头可以直接粘 JSON**

请求头那一行右边多了 **逐条 / JSON** 切换：

- JSON 模式里是一个文本框，切过去时**用当前的请求头填好**，改完立刻生效，并显示"当前生效 N 个请求头"；
- 同时接受**对象** `{"Content-Type": "application/json"}` 和**每行一条** `Name: value`（很多人是从 curl
  命令里复制过来的）；
- 值可以是字符串、数字、布尔，或它们的数组（会按 HTTP 的写法用逗号连接）；
- **写错了会明确报错，不会静默吞掉**：`{ "X-Broken": }` 会说"这不是 JSON"，而**不会**被当成一个叫
  `{ "X-Broken"` 的请求头 —— 这正是这类输入框最容易犯的错；
- 出错时**原有的请求头原封不动**（不会把你已经填好的清掉）。

**接口调用历史，以及一个能编辑已保存请求的区域**

- 每次发送（**包括超时和被拒绝的**）都会记一条：方法、URL、状态码或失败、耗时、多久以前；
- 点一条就把它**整套**放回编辑器（方法、请求头、正文都在，不只是 URL）；
- 每条可以 **存下**（变成一条命名的已保存请求）、**×** 删掉；历史区可以**一键清空**；
- 已保存区支持**点开载入**、**改名**（就地编辑，回车确认 / Esc 取消）、**覆盖**（用编辑器里的内容覆盖这一条）、
  **删除**；当前正在编辑的那条会高亮；
- 历史最多保留 **60 条**，由存储层强制（渲染层也裁）—— 一个写错的渲染进程不该能把磁盘写满。存的是**最新的**
  60 条，不是最早的：快照里塞 70 条、重载后是 60 条，最上面是第 0 条、第 69 条已经不在。

## 验证

完整闸门 `npm run verify`：41 套件全过。`smoke:rest` 35 → **60 条**：

- 布局 4 条（上面那些数字），含"正文 40 行后响应仍在屏内"；
- JSON 请求头 6 条：切换后已填好、写错报错、写错不动已有的、合法 JSON 变回逐条、**并且真的发到了服务端**
  （在服务端一侧核对收到 `x-from-json: yes`，而不是只看界面）；
- 历史 11 条：每条发送都在（含失败）、点开恢复整套、存下/改名/删除、超上限按最新裁剪。

顺带修好的两个探针问题：一是"拒绝连接"那一步原先等的是"屏幕上有错误"，而上一步超时留下的错误还在，于是
**断言其实是冲着旧错误的**（现在等 `ECONNREFUSED` 这个回答本身）；二是发现历史写入用了过期的 ref，
连发两次会丢一条 —— 现在 ref 与 state 同步更新。
