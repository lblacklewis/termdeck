## 3. 按需加载 —— 做完，但结论和当初的预期不同

设置抽屉 / 主机页 / 已知主机页 / 片段页 / 日志页 / SFTP 面板改成 `React.lazy` +
`<Suspense fallback={null}>`，包在**原来的渲染处**；`.td-page` 容器仍由页面自己渲染，
没被 Suspense 拆开（拆开会动到探针的 `elementFromPoint` 断言）。`SftpPanel` 从
`DrawerSections.tsx` 拆成独立模块，否则 App 只要静态引 `SectionFrame`/`HistoryPanel`，
同一模块里的 SFTP 面板就仍然留在首屏。

实测：首屏 **2,145,898 → 2,054,207 B（−91,691 B，−4.3%）**，拆出 6 个 chunk 共 97,192 B。

**原文档「预期 1200 KB」不成立**：那六个页面加起来只有 95 KB。首屏那 2 MB 是依赖 ——
dockview ~344 KB、xterm ~325 KB、react-dom ~204 KB、App.tsx 自身 ~170 KB。按需加载省的是
启动时那一段代码的解析，不是字节数的大头。

**真正的杠杆是 minify**：`electron-vite` 的 `build.minify` 默认是 `false`，之前发出去的
renderer 是 **47,039 行未压缩代码**。只给 renderer 打开（main/preload 保持不压缩，崩溃栈
可读）后：2,054,207 → **1,080,112 B**，CSS 276,740 → 206,966 B。

主题表没拆：`useTheme`/`useSettings` 首屏就要按 id 解析当前主题，而且它只有 16 KB 源码。

## 1. 拆 App.tsx —— 按文档的三个边界完成

| 边界 | 模块 | 装的是什么 |
| --- | --- | --- |
| 设置接线 | `components/SettingsDrawer.tsx` | 设置 Drawer + 懒加载的 SettingsDialog + Suspense 边界 |
| 终端页 | `components/useTabMenu.ts` | 标签右键菜单、菜单项、窗格重载、复制连接、排列对话框的开关与应用（367 行） |
| 终端页 | `components/DrawerFooter.tsx` | 抽屉底部工具条（⇶/⏱/▦/＋/&gt;_/⧉/⌨/⚙）、番茄钟 chip、拖拽手柄、宽度条、落点提示 |
| 其余页面 | `components/PagesLayer.tsx` | 主机 / 已知主机 / 片段 / 日志四个页面的接线，以及它们的 lazy 声明 |

`App.tsx` 3589 → **3118 行**。搬移都是整块原样搬：`useCallback`/`useMemo` 的依赖数组一个没动，
两处子组件只收 state 和回调。

**没搬的两处，是有意为之**：

- **dockview bootstrap**（面板创建、renderer 注册、`onDid*` 监听）和窗格渲染。它们和
  `dockApiRef`/panel 参数/会话表缠得最深，搬它的风险大于收益 —— 下一个接手的人如果要做，
  建议先给 `TerminalPanel` 那一侧补两条探针再动。
- `isPaneDead`/`closeDeadPane`：十几行、只被两处调用，留在原地比塞进新模块更清楚。

**踩过的坑（重要）**：欢迎页**不能**搬进 `PagesLayer`。`.td-welcome` 是根元素里的全尺寸
flex 子元素（`height/width: 100%`，**不是** `position: fixed`），靠"排在最后"盖住外壳；
挪到侧栏前面会变成「侧栏 + 欢迎页并排」，首次启动布局就变了。所以它留在 App 末尾，
`PagesLayer` 的注释里写了原因。

## 4b. 未用变量 / void 残留 —— 做完

两个开关**没有**写进 tsconfig（按原文档要求只作审计）：`web 14 条 + node 1 条`，现在都是 0。

清掉的东西：`App.tsx` 未用的 `LayoutState`/`SessionFolder` 类型、没人调的 `gridSize()`、
`autoSaveQuickConnect` 的 `session` 形参、`contextMenuItems` 里未解的 `const { session }`；
`HostsPage` 的 `folderOf()` 和 `hostMenu(session)` 形参；`SessionTree` 四个早就不用的
`onEditSession`/`onDeleteSession`/`onDuplicateSession`/`onDeleteFolder`；`useTerminal` 只写不读的
`lastFitW`/`lastFitH`；`Stores.remember()` 的 `at` 形参和结尾的 `void at`；`DEFAULT_BREAK_STATS`。

**`ipc.ts` 的主进程按键装配器整块删掉了**（`typing` 表 + `noteTypedInput` + 三处清理调用）：
它现在只是把拼出来的行 `void line` 丢掉 —— 记录早就搬到渲染层了（回车那一刻从屏幕读回那一行，
再发 `history:record`），留着只会误导人以为还有兜底。

其余 `void api.somePromise()` 都是**漂浮 promise 的写法**，不是残留，别删。

## 5. 内存泄漏三处 —— 复查完，改了两处

1. **广播注册表**：摘除路径本来就是完整的 —— `useTerminal` 的 dispose 里
   `unregisterTerminal`/`unregisterRefit`/`unregisterStamps`/`unregisterSink` 一个不少，
   而且和广播开关无关（广播开着关窗格也走这条）。**真正的泄漏是 `writesBySink`**：这张诊断表
   只增不减，应用开多久就攒多少个 session 条目 —— 已在 `unregisterSink` 里一起删。
2. **事件订阅**：`history:changed`/`settings:changed`/`tree:changed`/`tags:changed`/
   `session:data|error|exit`/`quit`/`fullScreen` 全部由 preload 的 `on()` 返回 `removeListener`，
   App 每个 `useEffect` 都把返回值交回去了。**无需改动**。
3. **排列的双 rAF**：确认会踩到已销毁的 group。`equalise` 现在先取一次 `api.groups` 快照，
   只对还在网格里的 group 设尺寸（顺带去掉那个没意义的 `void api`）。

**顺手发现但没改**：`tile.ts` 的 `equalise()` 里 `seen` 是跨两趟共用的，所以**第二趟其实什么
都不做** —— 注释说"一次为刚请求的布局、一次为 dockview 真正完成之后"，但第二趟每个 group 都已在
`seen` 里被跳过。改成每趟独立会让第二趟真的生效，那是行为变化，收尾时没动。

## 这一轮修的探针（都是探针自己过时，不是功能）

- `ui4` **28/29 → 55/55**：捷径菜单段在 `Save settings` 之后还去点 `Close`（抽屉已经关了），
  那一次 `click` 抛错把整段输出全吞掉。同一类 bug 还在 **ctxmenu**（→17/17）、
  **features3**（→50/50，它的「字体实时预览」因此被静默跳过很久）、**scale**（→36/36）各有一份。
- **drawer 52/59 → 59/59**：历史记录改由渲染层发出后，探针还直接 `writeSession` 写 pty ——
  那条路永远不会被记录。改成走 app 用的同一个 IPC（行内容的提取由 `smoke:suggest` 负责断言）。
- **onboarding 32/33 → 34/34**：「点当前页不要收起栏」是旧行为，`selectPage` 现在故意 toggle。

**记住这条**：这批探针最常见的坑是「**保存设置会关掉抽屉**」—— 之后再读抽屉里的东西必然是 null。
